整体架构设计 v2：三进程 + Edge 内双模块

本节只确认部署结构、模块职责和三类请求的进入方式。绿色表示核心业务事实，紫色表示设备事实，蓝色表示统一入口与身份能力。

目标设计：3 个 JVM 进程Core 仍是模块化单体IoT 独立保存设备事实当前代码仍是 4 个健康检查骨架

Platform Edge · :10001

一个部署进程，两个职责清晰的内部模块。

Gateway 模块路由、入口过滤、Token 基础校验、粗粒度功能授权、异常包装
Identity / Auth 模块登录、用户、租户成员、角色、权限、菜单、Token 签发与身份生命周期

Platform Core · :10003

黄金业务闭环的业务事实与最终业务授权。

purchasing / sales采购与销售业务意图
inventory余额、预留、移动、流水唯一事实源
manufacturing / quality工单、执行、报工与质检
trace / dashboard / ai只读投影与受控查询

Platform IoT · :10004

独立接收并保存设备事实，Core 故障时继续工作。

Device Access设备、设备凭证、MQTT QoS 1 去重
Device FactsTelemetry、Status、Alarm 与待补充业务上下文
↓ 同一 PostgreSQL 实例，保持逻辑数据所有权 ↓
Identity 数据用户、租户成员、角色、权限、菜单；与 Edge 同进程，但不与 Core 业务表混写。
Core 数据采购、销售、库存、制造、质量与追溯事实。
IoT 数据设备、遥测、状态、告警；禁止直接修改 Core 表。

① 登录请求

Browser → Edge
↓
Gateway 允许匿名登录路径
↓
Identity 校验租户 / 账号 / 锁定状态并签发 Token

② 普通业务请求

Browser → Gateway Filter
↓
验证身份与功能权限
↓
Core 再校验租户、单据状态、自审限制和业务不变量

③ 设备上报

Device → Mosquitto
↓
IoT 校验 DeviceCredential
↓
先保存遥测 / 状态 / 告警，再延后补充 Core 上下文
入口不是最终授权Gateway 放行后，Core 仍保护具体业务对象。
合并部署，不合并职责Gateway 与 Identity 有内部接缝，可独立测试和未来拆出。
唯一事实源库存事实属于 Core；设备事实属于 IoT。
一人多角色但不可自审RBAC 给资格，Core 对具体单据执行职责分离规则。
本节待确认：一期以 Edge、Core、IoT 三个部署进程为目标；Edge 内部保留 Gateway 与 Identity/Auth 两个清晰模块。
