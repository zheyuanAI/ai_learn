## 说明
- `specs/` 是当前长期领域规格事实源；`prototype/` 保留原位，避免打断现有原型资源路径和领域分组。
- 规格与原型描述的是批准后的目标能力；当前已实现能力必须以实际代码和配置为准。
- `openspec/` 仅承载显式 OpenSpec 任务的流程、schema 与协作工件，不替代 `specs/` 事实源。
- 通用说明文档、计划文档和协作规则统一从 `docs/` 进入和维护。
