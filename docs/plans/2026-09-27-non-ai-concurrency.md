# 非 AI 并发与真实流程验收计划

用户已授权继续处理非 AI 项目问题，并要求最后清理数据库后按真实岗位顺序执行现实化业务数据流程。AI 功能和 AI 工具链不在本次修改范围，安全检查仅保留租户、幂等与数据一致性必要边界。

1. 库存：复现外层事务分段加锁风险，通过既有库存应用端口预锁整笔业务所需维度；覆盖销售履约、采购收货、调拨、盘点和多行领退料。
2. IoT：把实例级串行改为租户/设备级串行，锁覆盖事务完成，空闲锁及时释放；验证重复、延迟、异常及不同设备并行。
3. 前端：冻结现有非 AI `useCommand` 首次载荷、对象 ID 和业务时间；验证改变表单后的同键重试。
4. 工程验证：启动 `127.0.0.1:55432` 的独立 PostgreSQL 12.1，运行真实迁移与库存并发测试；建立自动构建回归配置与可重复的逐级压测入口。未给定容量目标时只报告实测，不承诺容量。
5. 业务操作记录：复用 Core 本地操作记录端口，先补采购订单成功动作及收货；保持同业务事务和幂等重放去重。
6. 真实流程：先备份确认过的 `127.0.0.1:5433/ai_learn`，按软删除规则清理旧业务数据，保留认证权限、迁移历史及 AI 数据；启动非 AI 服务，以真实账号和岗位顺序执行客户订单、工单、采购、拒收/分批收货、质检上架、领退料、报工质检、成品入库、拣货发货和追溯。使用行业化名称、非整齐数量、批次及现场异常，记录每步账号、事实 ID、库存对账与浏览器证据。

不手工修改生成目录，不改依赖版本或基础设施编排，不执行 Git 提交。后端最终执行聚合 `mvn package`（提供真实隔离库参数，不排除 Auth 迁移测试），前端执行单测与 `npm run build`；真实角色验收必须在修复后的服务上执行。

本轮六项已完成：后端 411 项测试与 package、前端 181 项单测与 build 通过；备份清库后的六岗位 85 步真实接口/MQTT 流程、六岗位页面复验与 1/5/10/20 并发的 2,000 次 GET 基线均通过。实际数量、日志、截图和容量限制见 [最终验收记录](../verification/2026-09-27-non-ai-concurrency-and-role-flow.md)。采购详情的完整累计查询、MQTT 消费吞吐扩展、多岗位并发写入及长期容量测试仍是后续范围，未在本轮冒充完成。
