# 非 AI 剩余并发与采购详情收口计划

用户在 2026-09-27 六岗位验收后要求继续。本轮只处理该次验收明确留下的三项：采购详情累计查询、MQTT 消费吞吐边界、隔离环境中的并发写入与持续运行观测。AI 功能、认证结构和部署编排不在范围内；保留原工作区未提交改动。

1. **采购订单行事实**：从实际生效的订单、收货、质检、处置和上架持久化关系追踪订单行 ID，按租户及有效数据筛选并聚合，补充现有 `GET /api/purchase-orders/{id}` 的行累计字段。前端沿当前字段展示真实零值，不能按 SKU 猜测多行分摊。覆盖同 SKU 多行、多批次、重复请求和已删除事实；同步接口契约。
2. **MQTT 消费边界**：核对 Paho 1.2.5 的 QoS 1 确认行为及现有连接、重连和事务链。只有在可证明提交后确认、失败重投、有界背压且同设备有序时才实现并行消费；否则保留可靠串行路径，给出可复现实测和具体限制，不以异步返回替代成功提交。
3. **写入基线**：建立仅针对随机隔离 PostgreSQL 库和本轮拥有服务的可重复测试工具，输入使用已定义 DTO 和幂等键。分开观测热点库存写入与跨岗位写入，记录每档请求成功率、吞吐、P95/P99、可见锁等待和持续时间。未给出容量目标，仅报告结果与环境，不承诺生产规模。不得自动写入或清理 `127.0.0.1:5433/ai_learn`。
4. **整体验证**：各模块专项回归通过后，以本项目 JDK 21/Maven 3.9.1 完整 `mvn package`，Node 20 完整单测及 `npm run build`；在独立环境实际执行可行的吞吐与写入场景。若需要复验开发库六岗位流程，必须先再次备份并按既有软删除/事实表维护脚本清理，然后按真实岗位顺序执行。最终在 `docs/verification/` 记录成功、失败现场、未完成边界及命令证据，不提交 Git。

设计选择：采购以持久化关系而非物料相等判断归属；MQTT 优先不破坏 QoS 1 可靠性；容量测试优先独立库和限流分档。关键技术可行性由代码、实际依赖和专项测试决定，不补造未定义接口或队列语义。
