## 1. 项目主线

本计划只围绕一条黄金业务闭环推进：

```text
销售订单需求
  -> 人工关联生产工单
  -> 根据 BOM 人工判断缺料并关联采购
  -> 采购收货进入收货暂存位
  -> 上架只移动位置
  -> 生产领料
  -> 派工与工序执行
  -> MQTT 遥测、状态、告警与恢复
  -> 报工、质检、成品入库
  -> 销售库存预留
  -> 拣货到发货暂存位
  -> 发货并完成交付
```

一期不实现自动 MRP、APS、WIP/线边仓、完整财务、真实 PLC 协议、三维数字孪生、RAG 和生产级高可用。

## 2. 每周共同完成定义

每周交付必须同时包含：

- 学习记录：说明本周理解了什么领域问题，不只记录技术 API；
- 术语确认：有歧义的概念先更新 `CONTEXT.md`；
- 规格与原型：领域规则、目标接口、页面和验收一致；
- 实现：只实现本周闭环必需能力；
- 自动化验证：覆盖关键不变量、状态迁移、租户隔离和幂等；
- 人工验收：能用稳定演示数据复现当周场景；
- 状态说明：明确区分“已设计”“已实现”“已验证”。

## 4. 分阶段学习重点

### 第 1 周：从开源项目提炼语义

- 从 jshERP 学习单据表头/明细、采购和销售流程，但不把“单据多”当成项目核心。
- 从 OpenWMS 学习收货、上架、拣货、发货及显式状态，但按本项目的库存时点重新确认。
- 从 ThingsBoard 学习设备、遥测、状态和告警的区别，但一期只使用 MQTT 模拟接入。
- 学习成果必须回到本项目术语、状态和验收，禁止直接复制参考工程模型。

### 第 2—4 周：先把库存事实做可信

- 余额是查询快照，预留表达业务占用，流水记录发生过的事实。
- 所有库存写操作通过库存应用服务；其他模块不得直接更新余额。
- 收货、上架、预留、释放、拣货、发货分别使用明确命令，不能合并成含糊的“库存更新”。
- 幂等解决重复命令，并发控制解决同时竞争库存，数据库事务保证同一命令内一致。
- 人工供需关联只说明“为何产生”和“进度如何”，不承担 MRP 运算。

### 第 5—6 周：区分制造意图与现场事实

- `WorkOrder` 是生产意图，`DispatchOrder` 是执行安排，`OperationExecution` 是一次实际执行。
- 领退料连接仓库原料事实，成品入库连接合格产出与库存事实。
- 报工数量必须可解释，合格、不良、已入库之间存在明确上限。
- 一期不扩展 WIP、线边仓、自动排程、返工和复杂质检。

### 第 7 周：让 IoT 能独立成立

- 遥测是原始时序事实，状态是当前快照，告警有触发、确认和恢复生命周期。
- MQTT QoS 1 可能重复投递，必须使用设备与消息标识去重。
- IoT 先保存设备事实，再补充生产上下文；Core 不可用时不丢已接收数据。
- 设备优先关联工作中心/区域，工序执行可选关联设备；自动关联不可靠时允许人工补充。

### 第 8—9 周：从事实构建查询体验

- 追溯、异常中心、地图和看板是查询模型，不修改源业务事实。
- 异常保持库存异常、生产异常、设备告警三类领域语义。
- AI 只通过受控应用服务工具查询，并继承用户租户与权限。
- 每次 AI 工具调用记录来源、时间范围、输入输出摘要、耗时和结果。
- Cesium/三维、知识库/RAG、MinIO、pgvector 均只保留二期设计资产。

## 5. 五项架构硬验收

1. 库存余额或预留每次变化都有对应事实；上架不重复增库，拣货不等于发货。
2. 事务、幂等和并发控制共同保证可用库存不为负，重复命令不重复产生事实。
3. 非法状态迁移由后端拒绝，任何业务关系不得跨租户。
4. MQTT 重复消息不重复生成遥测或告警，Core 故障不影响 IoT 保存已接收事实。
5. 任一库存流水可追溯明确来源，黄金闭环不存在只供展示的孤立关联。

## 6. 当前工程基线

- 后端：Java 21、Maven 3.9.1、Spring Boot 3.3.5；Gateway/Auth/Core/IoT 端口依次为 10001/10002/10003/10004。
- 前端：Node 20、Vue 3、Vite 5、TypeScript。
- 一期中间件：PostgreSQL 16（5433）、Redis（6379）、Mosquitto（1883）。
- 当前代码只有工程骨架与 `/internal/ping`，业务 API、数据库映射、鉴权、MQTT 和前端真实请求均尚未实现。
- RabbitMQ、MinIO、pgvector 属于二期候选，不作为一期本地启动条件。

## 7. 沟通检查点

遇到以下问题必须暂停具体实现并与项目负责人确认：

- 同一术语在销售、库存、制造中含义不同；
- 库存应在何时增加、移动、预留、扣减或回补；
- 状态迁移会影响其他领域对象；
- 需要新增跨域关系、自动决策或修改一期范围；
- 为了页面效果准备建立第二套业务数据；
- 开源参考实现与本项目正式规格冲突。
