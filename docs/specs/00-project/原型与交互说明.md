# 原型范围

一期原型服务于一个月内交付的黄金业务闭环。二维地图、综合看板和 AI 助手仅提供轻量只读展示与查询；数字孪生仿真和知识库训练属于二期，不进入一期实现与验收。

## 一期必须实现的原型页面
- 登录页
- 首页综合看板
- 商品、仓库、收货暂存位、发货暂存位、普通库位管理
- 采购单、入库单、上架任务页
- 销售单、拣货任务、出库单页
- 工单列表、工单详情、领退料、派工、工序执行、报工与质检页
- 设备列表、设备详情、告警页
- 厂区二维地图页
- AI 助手聊天页、追溯查询页、调用审计页

## 二期原型资产

- 三维展示页：保留现有页面用于二期讨论，不进入一期实现与验收
- 知识库管理页：保留现有页面用于二期知识库训练和 RAG 设计，不进入一期实现与验收

## 原型阶段交付要求
- 使用假数据即可
- 原型必须建立在已确认的业务目的、角色职责、状态流转和业务规则之上，不以页面布局代替业务分析
- 先固定字段、列表列、详情页结构、状态标签、主要操作按钮
- 每个页面标出需要的接口、权限点、状态流转
- 产出页面导航图和主流程跳转图

### 销售交付高保真原型要求

- 同时展示销售订单生命周期和动态履约进度，不再用 `Reserved / Picking / Shipped` 作为订单主状态
- 以订单行展示预留、拣货、发货数量及未预留、未拣、发货暂存和未发货数量
- 正常操作区只提供“直接拣货”和“发货”；直接拣货在同一事务内自动预留本次数量，并在结果中展示预留变化摘要
- 退回未发货拣货和释放未拣预留只进入异常处理区，不作为正常履约步骤
- 可切换部分履约、人工完成和正常完成三个示例场景
- 根据销售人员、仓库人员和当前状态展示可执行动作及禁用原因
- 演示直接拣货中的自动预留、直接拣货、发货以及异常退回/释放、人工完成的输入校验与结果反馈
- 明确标注页面为目标设计，不能将浏览器内假数据操作表述为接口已经实现

### 采购入库高保真原型要求

- 将采购来源关联、仓库到货验收、生产质检、质量处置决定、仓库执行确认和上架拆成可辨识的节点，不再使用“收货质检上架”一个复合动作代替全部职责
- 仓库到货外观验收只展示 `arrived_qty（到货数量）`、`rejected_qty（收货前拒收数量）` 和 `received_qty（实际接收数量）`，并提示 `arrived_qty = rejected_qty + received_qty`
- 实际接收数量全部进入 `QualityHold（质量隔离位）`；采购到货质检单独展示 `inspected_qty（检验数量）`、`qualified_qty（质检合格数量）` 和 `unqualified_qty（质检不合格数量）`，并提示 `inspected_qty = qualified_qty + unqualified_qty`
- 部分或全部拒收时要求仓库人员填写拒收原因，明确拒收数量不进入库存、不计入累计已收货并继续作为待收数量
- 生产质检人员记录质量结论；放行/报废由生产质检人员决定，退回供应方由采购人员决定并协调，实际移位或扣减由仓库人员确认
- 处置详情同时展示 `PendingDecision（待决定）`、`PendingExecution（待执行）` 与 `Completed（已完成）`，并区分“决定已作出”和“实物已处理”
- 现有静态采购页面已同步“外观验收 -> 全部接收进入质量隔离 -> 到货质检 -> 质量处置 -> 上架”规则，作为后续高保真采购入库原型的评审基线

## 设计与实现顺序

一期采用按业务模块逐段冻结的方式推进：

```text
业务理解与规则
  ↓
领域对象、角色职责与状态流转
  ↓
低保真原型
  ↓
接口契约
  ↓
数据库与接口实现
  ↓
前后端联调和场景验收
```

截至 2026-08-28，全部一期业务模块的规则确认和书面规格复核已经完成；销售高保真页面已按直接拣货规则更新，后续可按黄金闭环顺序继续制作采购、生产与其他模块高保真原型。

不要求画完全部高保真页面后才开始接口设计。每个模块的低保真原型只要确认列表、详情、表单、操作按钮、状态和权限，即可进入该模块的接口契约评审。

## 原型验收
- 能串起一期黄金业务闭环，并分别演示采购到货拒收/实际接收/到货质检/质量处置/上架、生产领退料与执行、销售直接拣货（内部自动预留）/发货、MQTT 告警、跨域追溯、二维地图和 AI 只读查询
- 每个关键单据至少包含列表、详情、创建/提交/确认等核心动作
- 二维地图、看板、AI 只读工具页面有明确的数据占位与交互说明
