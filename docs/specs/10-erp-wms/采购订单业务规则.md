# 采购订单业务规则

> 状态：一期目标设计已确认  
> 确认日期：2026-08-28

## 1. 目标与边界

采购订单表达向供应方采购指定产品和数量的业务意图，支持提交、审核、分批到货验收、收货前拒收、实际接收、质量处理、分批上架、正常完成和人工完成。

采购明细可以人工关联来源生产工单，用于追溯，不触发 MRP（物料需求计划）、自动缺口计算或自动采购建议。

## 2. 状态与修改

```text
未提交 -> 已提交 -> 已审核 -> 部分收货 -> 已完成
```

- 只有未提交状态允许修改供应商、产品、数量、计划到货日期和来源生产工单。
- 已提交后等待采购角色审核；审核不自动收货或增加库存。
- 已审核后可以分批收货；首次部分收货后显示“部分收货”。
- 全部采购数量完成收货后正常完成；也允许填写原因后人工完成剩余数量。

## 3. 分批收货

- 每次到货验收的 `arrived_qty（到货数量）` 必须大于零，且不得超过采购订单明细当前待收数量。
- 仓库到货验收只记录 `rejected_qty（收货前拒收数量）` 和 `received_qty（实际接收数量）`，不在收货时判断质量合格数量。
- 收货数量关系固定为：`arrived_qty = rejected_qty + received_qty`；各数量不得小于零。
- `rejected_qty` 表示仓库在确认接收前发现包装破损、型号明显错误、数量争议等问题而拒绝接管的数量。拒收数量不增加库存、不计入采购累计已收货，并继续保留为待收数量，等待供应方补送；采购人员后续也可通过人工完成终止该余量。
- `rejected_qty > 0` 时必须填写 `rejection_reason（拒收原因）`，并保留操作账号、会话标识和时间。允许全部拒收，即 `received_qty = 0`；此时仅生成到货拒收事实，不生成库存余额变化或库存流水。
- 只有 `received_qty` 在收货确认时增加实物库存并形成采购来源库存流水；实际接收数量尚未完成采购到货质检，必须全部进入 `QualityHold（质量隔离位）`，不得直接进入 `ReceivingStaging（收货暂存位）`。
- 同一收货命令重复提交只生效一次；失败时不得部分增加库存。
- 收货记录必须保留采购订单、明细、产品、到货/拒收/实际接收三类数量、拒收原因、质量隔离库位、操作人和时间。

## 4. 质量与上架

- 实际接收货物全部进入 `QualityHold`（质量隔离位：实物已经由企业接管，但在放行前禁止正常使用）。
- 生产质检人员对质量隔离货物执行采购到货质检，记录 `inspected_qty（本次检验数量）`、`qualified_qty（质检合格数量）` 和 `unqualified_qty（质检不合格数量）`，并满足 `inspected_qty = qualified_qty + unqualified_qty`；累计检验数量不得超过对应累计实际接收数量。
- 检验只形成质量事实，不直接移动或扣减库存。合格货物等待放行执行，不合格货物继续隔离并等待退回供应方或报废决定。
- 质检合格数量只能进入放行处理；质检不合格数量只能退回供应方或报废。仓库确认实际处置前，质量隔离货物不得参与销售预留、生产领料或上架。
- 质量处置分为“业务决定”和“仓库执行确认”两个时点：生产质检人员决定放行或报废；采购人员决定并协调退回供应方；仓库人员确认实际移位、退回出库或报废扣减。
- 检验记录进入 `PendingDecision（待决定）`，处置决定后进入 `PendingExecution（待执行）`，仓库人员确认实物处理后进入 `Completed（已完成）`。放行执行把实物从质量隔离位移到收货暂存位，之后仍须单独上架；退回和报废执行必须减少质量隔离位库存并生成来源明确的库存流水。
- 上架只把实物从暂存/放行位置移至目标存储位，不重复增加企业总库存。
- 累计上架数量不得超过对应已收货且允许上架的数量。

## 5. 正常完成与人工完成

- 全部订单明细完成收货后进入“已完成（正常）”。
- 采购人员可以对已审核或部分收货订单执行“已完成（人工）”，终止剩余未收货数量。
- 人工完成必须填写原因，并记录账号、会话标识和时间。
- 人工完成不补造收货、质量处理、上架或库存流水。

人工完成后的货物处理：

| 货物情况 | 后续规则 |
| --- | --- |
| 已收货且质检合格 | 完成放行执行后仍可继续上架，不受采购订单人工完成影响 |
| 已收货但待检/质检不合格 | 继续留在质量隔离位，完成检验、放行、退回或报废处置 |
| 已收货且决定报废 | 必须填写原因并生成库存减少流水，不得直接删除 |
| 尚未收货 | 随订单人工完成而终止，不再生成收货或上架任务 |

采购订单完成状态与已收货货物的仓储任务相互独立：订单可以已经人工完成，但已存在的上架和质量处置任务仍必须完成或关闭。

## 6. 异常与审计

- 超量到货、收货或质检数量关系不成立、拒收原因缺失、超量收货、超量检验、超量处置、超量上架、非法状态、无效来源、跨租户引用和库存确认失败均拒绝整次命令。
- 退回供应方必须保留退回数量、原因和实物出库事实；一期若未实现完整采购退货单，则不得把退回描述为已经实现。
- 所有到货拒收、收货、质量决定、仓库执行、上架、人工完成和报废操作均须可追溯到采购订单；只有实际库存变化关联库存流水。

## 7. 一期边界

- 不包含询价、比价、采购合同、付款、应付、发票和供应商对账。
- 不实现自动采购建议、自动补货或自动生成采购订单。
- 复杂抽样检验、索赔和供应商绩效进入后续阶段。
