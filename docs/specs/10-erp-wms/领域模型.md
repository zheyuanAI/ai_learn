# ERP/WMS 领域模型

## 核心实体
- 主数据：`Product`、`Warehouse`、`Location`、`Customer`、`Supplier`
- 库存内核：`InventoryBalance`、`InventoryReservation`、`InventoryReservationAllocation`、`InventoryTransaction`
- 入库：`PurchaseOrder`、`PurchaseReceipt`、`PurchaseQualityInspection`、`PurchaseQualityDisposition`、`PutawayTask`
- 出库：`SalesOrder`、`PickTask`、`SalesShipment`
- 调整：`TransferOrder`、`StocktakeOrder`

## 通用字段约束
- 所有主数据和业务单据必须带：`id`、`tenant_id`、`status`、`created_by`、`created_at`、`updated_by`、`updated_at`
- 所有明细行必须带：`line_no`、`product_id`、`uom`、`qty`
- 库存维度固定为：`tenant_id`、`product_id`、`warehouse_id`、`location_id` 与可选 `lot_no`
- 一期仅支持可选的简单批次；序列号、生产日期、保质期及组合校验属于二期

## 库位类型
- `ReceivingStaging`：收货确认后的收货暂存位
- `Storage`：普通存储位
- `Picking`：可拣货位
- `ShippingStaging`：拣货完成、等待发货的发货暂存位
- `QualityHold`：已形成实物库存但暂时禁止正常使用的质量隔离位
- `Adjustment`：仅供盘点或异常调整使用的受控库位

## 页面与模型字段

### `InventoryBalance`
- 唯一维度：租户、产品、仓库、库位、可选批次
- 字段：`on_hand_qty`、`reserved_qty`、`available_qty`、`version`、`last_transaction_at`
- 不变量：`available_qty = on_hand_qty - reserved_qty` 且 `available_qty >= 0`

### `InventoryReservation`
- 字段：`reservation_no`、`source_type`、`source_id`、`source_line_id`、`reserved_qty`、`released_qty`、`status`
- 状态：`Active -> PartiallyReleased -> Released`；取消业务时也必须以释放动作结束，不删除历史

### `InventoryReservationAllocation`
- 字段：`reservation_id`、库存维度、`allocated_qty`、`released_qty`、`version`
- 语义：表达一笔业务预留当前分配在哪个库位；同一预留可以拆分到多个库位
- 不变量：同一预留的有效分配量合计等于 `reserved_qty - released_qty`；每个库位的有效分配量计入对应 `InventoryBalance.reserved_qty`
- 拣货和退回在同一事务内迁移库位实物与有效预留分配，不增加 `released_qty`；发货或主动释放才减少有效分配并增加 `released_qty`

### `InventoryTransaction`
- 字段：`transaction_no`、`transaction_type`、`source_type`、`source_id`、`source_line_id`、`from_location_id`、`to_location_id`、`qty`、`occurred_at`、`operator_id`
- 流水追加后不可随意修改；纠错必须生成反向或调整流水

### `PurchaseOrder`
- 表头：`po_no`、`supplier_id`、`expected_arrival_date`、`status`、`remark`
- 明细：`product_id`、`ordered_qty`、`received_qty`、`pending_qty`、`target_warehouse_id`、可选 `source_work_order_id`
- 完成审计：`completion_type`、可选 `completion_reason`、`completed_by`、`completed_session_id`、`completed_at`

### `PurchaseReceipt` 与 `PutawayTask`
- 收货：`receipt_no`、`purchase_order_id`、`receipt_time`、`quality_hold_location_id`、`status`
- 收货明细：`product_id`、`arrived_qty`、`rejected_qty`、`received_qty`、`putaway_qty`、可选 `rejection_reason`、可选 `lot_no`
- 仓库到货验收数量必须满足 `arrived_qty = rejected_qty + received_qty`；仓库不在收货时填写质量合格或不合格数量
- `rejected_qty` 不进入库存、不计入采购累计已收货，并继续保留为采购待收数量；`rejected_qty > 0` 时 `rejection_reason` 必填并记录操作账号、会话标识和时间
- 上架：`task_no`、`purchase_receipt_id`、`product_id`、`from_location_id`、`to_location_id`、`putaway_qty`、`status`

### `PurchaseQualityInspection` 与 `PurchaseQualityDisposition`
- 检验字段：`purchase_receipt_id`、`purchase_receipt_line_id`、`product_id`、`inspected_qty`、`qualified_qty`、`unqualified_qty`、`inspected_by`、`inspected_at`、可选检验说明
- 检验数量必须满足 `inspected_qty = qualified_qty + unqualified_qty`；检验结论由生产质检人员记录，累计检验数量不得超过对应收货明细的 `received_qty`
- 处置字段：`purchase_quality_inspection_id`、`disposition_type`、`disposition_qty`、可选 `reason`、`status`、可选 `decided_by`、可选 `decided_at`、可选 `executed_by`、可选 `executed_at`、可选 `inventory_transaction_id`
- `disposition_type` 至少区分放行上架、退回供应方和报废
- 放行数量不得超过对应质检合格未处置数量；退回供应方与报废数量合计不得超过对应质检不合格未处置数量
- `status` 使用 `PendingDecision（待决定） -> PendingExecution（待执行） -> Completed（已完成）`；检验和业务决定不得提前改变库存，仓库执行确认后才形成实际位置或数量变化
- 放行和报废由生产质检人员决定；退回供应方由采购人员决定并协调；实际移位、退回出库或报废扣减由仓库人员确认
- 放行执行把实物从质量隔离位移到收货暂存位；退回和报废执行必须生成库存减少流水，已经收货的实物不得通过删除记录消失

### `SalesOrder`
- 表头：`so_no`、`customer_id`、`planned_ship_date`、`status`、`remark`
- 明细：`product_id`、`ordered_qty`、`reserved_qty`、`picked_qty`、`shipped_qty`
- 完成审计：`completion_type`、可选 `completion_reason`、`completed_by`、`completed_session_id`、`completed_at`
- 一个销售订单允许产生多笔预留、多张拣货任务和多张发货单；明细数量满足 `0 <= shipped_qty <= picked_qty <= reserved_qty <= ordered_qty`
- `reserved_qty` 表示仍被有效预留或已经进入下游的数量，`picked_qty` 表示仍在发货暂存位或已经发货的数量，`shipped_qty` 表示累计发货数量
- `status` 只保存生命周期；`fulfillment_status` 由明细数量动态计算，不持久化
- `completion_type` 至少区分正常履约完成与人工完成。人工完成时 `completion_reason` 必填，并释放剩余有效预留

### `PickTask` 与 `SalesShipment`
- 拣货：`task_no`、`sales_order_id`、`sales_order_line_id`、`source_location_id`、`shipping_location_id`、`pick_qty`、`picked_qty`、`status`
- 发货：`shipment_no`、`sales_order_id`、`ship_time`、`carrier_name`、`status`

### `TransferOrder` 与 `StocktakeOrder`
- 调拨：`transfer_no`、`from_warehouse_id`、`from_location_id`、`to_warehouse_id`、`to_location_id`、`status`
- 盘点：`stocktake_no`、`warehouse_id`、`scope_type`、`status`、`system_snapshot_at`、`confirmed_at`
- 盘点明细：`product_id`、`system_qty`、`counted_qty`、`variance_qty`、`variance_reason`

## 库存关键时点

| 业务动作 | `on_hand_qty` | `reserved_qty` | 位置变化 |
| --- | --- | --- | --- |
| 收货前拒收 | 不变 | 不变 | 不进入企业受管库位 |
| 收货确认 | 仅按 `received_qty` 增加 | 不变 | 实际接收数量全部进入质量隔离位 |
| 采购到货质检 | 不变 | 不变 | 只记录合格/不合格数量，实物仍在质量隔离位 |
| 质量放行执行 | 总量不变 | 不变 | 质量隔离位 -> 收货暂存位 |
| 质量退回/报废执行 | 减少 | 不变 | 质量隔离位减少 |
| 上架确认 | 总量不变 | 不变 | 收货暂存位 -> 目标库位 |
| 销售直接拣货 | 总量不变 | 自动补足本次所需预留后，企业合计不变并随实物迁移库位分配 | 来源库位 -> 发货暂存位 |
| 退回拣货 | 总量不变 | 企业合计不变，随实物迁移库位分配 | 发货暂存位 -> 合法来源/拣货库位 |
| 发货确认 | 减少 | 释放对应预留 | 发货暂存位减少 |
| 生产领料确认 | 减少 | 不变 | 原料库位减少 |
| 生产退料确认 | 增加 | 不变 | 退回库位增加 |
| 成品入库确认 | 增加 | 不变 | 成品库位增加 |

## 状态机
- 采购单：`Draft -> Submitted -> Approved -> PartiallyReceived -> Completed`；`Completed` 可由全部收货或人工完成进入
- 收货单：`Draft -> Confirmed`
- 上架任务：`Pending -> Processing -> Confirmed`
- 销售单生命周期：`Draft -> Submitted -> Approved -> Completed`
- 销售单履约进度（派生）：`NotStarted / InProgress / FullyShipped`
- 库存预留：`Active -> PartiallyReleased -> Released`
- 盘点单：`NotStarted -> Counting -> ConfirmedAdjusted`，页面显示“未盘点 -> 盘点中 -> 已确认并调整”

`Completed` 由核心履约动作完成决定，不以应收/应付草稿是否生成作为状态门槛。

销售订单采用生命周期与履约进度双轴模型。页面正常路径为“审核通过 -> 直接拣货 -> 发货”，直接拣货在同一事务内自动补足本次数量所需预留；拣货和部分发货期间生命周期保持 `Approved`，只在全部发货或人工完成时进入 `Completed`。完整规则见 [销售订单业务规则](./销售订单业务规则.md)。

人工完成是受控终止动作：销售单人工完成释放剩余有效预留，采购单人工完成终止剩余未收货数量。两者均不补造库存事实，并保留原因、账号、会话和时间。采购单人工完成后，已经收货的合格货物仍可上架，质量隔离货物仍须完成放行、退回或报废处置。

库存和采购的完整规则分别见 [库存业务规则](./库存业务规则.md) 与 [采购订单业务规则](./采购订单业务规则.md)。

## 一致性与审计
- 所有库存变化只能由库存应用服务在同一事务内更新余额并追加流水/预留记录
- 相同 `tenant_id + endpoint + Idempotency-Key` 重复调用返回首次成功结果，不重复产生库存事实
- 更新余额时使用 `version` 乐观锁或数据库行锁；直接拣货中的并发自动预留总量不得超过可用库存
- 业务单据不可跨租户关联主数据或库存
- 预留失败不得产生有效预留；失败原因进入操作审计，不写伪库存流水
