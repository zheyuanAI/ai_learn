# ERP/WMS 验收清单

## 核心验收
- 收货前拒收数量不进入库存、不计入采购累计已收货，并继续保留为待收数量；拒收原因和操作审计可追溯
- 仓库收货只记录到货、拒收和实际接收数量，不提前填写质检合格或不合格数量
- 收货确认只按 `received_qty（实际接收数量）` 增加 `on_hand_qty` 并生成来源明确的库存流水，实际接收数量全部进入 `QualityHold（质量隔离位）`
- 采购到货质检满足 `inspected_qty = qualified_qty + unqualified_qty`；检验本身不改变库存，合格数量等待放行，不合格数量继续隔离
- 上架确认后，总 `on_hand_qty` 不变，仅暂存位减少、目标库位增加
- 销售页面正常路径只显示“直接拣货 -> 发货”；直接拣货在同一事务内自动补足本次数量所需预留
- 直接拣货确认后，实物和等量有效预留分配同步移动到发货暂存位，总 `on_hand_qty` 不变
- 发货确认后，发货暂存位实物库存减少并释放对应预留
- 同一销售订单可分批直接拣货和分批发货，每次操作只影响本次数量，自动预留、拣货和发货累计数量可回到订单明细核对
- 销售订单生命周期只使用 `Draft / Submitted / Approved / Completed`，履约期间保持 `Approved`
- `fulfillment_status` 根据明细数量派生，不作为数据库事实源；页面同时展示两个状态轴
- 每个销售订单行始终满足 `0 <= shipped_qty <= picked_qty <= reserved_qty <= ordered_qty`
- 销售单人工完成释放剩余有效预留，但不生成虚假的拣货、发货或库存流水
- 采购单人工完成不生成虚假的收货、上架或库存流水
- 采购单人工完成后，已收货合格货物仍可上架，质量隔离货物仍可放行、退回或报废
- 报废已收货货物必须填写原因并生成库存减少流水，不得直接删除库存记录
- 质量检验和处置决定均不提前改变库存；仓库人员确认实际执行后才移位或扣减库存
- 生产领料、退料和成品入库通过同一库存应用服务产生可追溯流水
- 调拨保持企业总库存不变；盘点差异以调整流水入账
- 盘点页面状态显示“未盘点 -> 盘点中 -> 已确认并调整”，确认时才生成差异调整流水

## 页面验收
- 商品列表展示：`sku`、`name`、`spec`、`uom`、`batch_managed`、`status`
- 库存页分别展示实物、预留、可用、库位、版本和最近流水
- 采购页明确区分收货与上架的库存影响，并展示可选来源工单
- 销售页正常操作区展示直接拣货和发货；自动预留作为直接拣货结果摘要展示，退回与释放只放在异常处理区
- 所有业务单据详情展示当前状态、来源关系和后端允许的操作

## 黄金链路相关场景

### 场景 1：采购收货与上架
- 前置：采购单已审批，质量隔离位、收货暂存位和目标库位启用
- 操作：仓库到货外观验收 -> 确认接收并全部进入质量隔离位 -> 生产质检人员完成采购到货质检 -> 合格数量放行执行 -> 确认上架
- 结果：仅实际接收数量增加总库存一次；质检不改变库存；放行和上架仅改变位置；库存流水均可回到采购明细

### 场景 1A：部分到货拒收
- 前置：采购单已审批，本次到货 100，其中 10 件外包装破损
- 操作：仓库人员填写 `arrived_qty = 100`、`rejected_qty = 10`、`received_qty = 90` 和拒收原因后确认
- 结果：只按 90 件增加库存和累计已收货；10 件保留到货拒收事实并继续作为待收数量，不生成库存流水

### 场景 1B：全部到货拒收
- 前置：采购单已审批，本次到货型号全部错误
- 操作：仓库人员填写 `arrived_qty > 0`、`rejected_qty = arrived_qty`、`received_qty = 0` 和拒收原因后确认
- 结果：生成到货拒收事实；库存余额、累计已收货和库存流水均不增加，采购订单仍保留对应待收数量

### 场景 1C：收货后质量隔离与处置
- 前置：采购单已审批，本次实际接收数量已经全部进入质量隔离位
- 操作：仓库确认接收并进入质量隔离位 -> 生产质检人员记录检验结论 -> 生产质检人员决定放行/报废，或采购人员决定退回 -> 仓库人员确认实际处理
- 结果：检验数量满足 `inspected_qty = qualified_qty + unqualified_qty`；检验和处置决定时库存不变；放行执行只移动合格数量到收货暂存位，退回/报废执行只扣减不合格的质量隔离库存并形成流水

### 场景 2：销售直接拣货与发货
- 前置：库存充足，销售单已审批
- 操作：第一次直接拣货 -> 第一次发货 -> 第二次直接拣货 -> 第二次发货
- 结果：每次直接拣货在同一事务内自动预留本次数量并完成移位；自动预留只影响可用量，拣货只影响位置，发货才扣减实物并释放本次对应预留

### 场景 3：销售订单人工完成
- 前置：销售订单已经审批，允许存在部分已发货数量和剩余有效预留；如存在未发货暂存数量，仓库人员先退回拣货
- 操作：销售人员填写原因并执行人工完成
- 结果：订单进入 `Completed + Manual`，剩余有效预留被释放；已发生的发货和库存事实保留；不补造剩余数量的拣货、发货或库存流水；记录账号、会话和时间

### 场景 4：采购订单人工完成
- 前置：采购订单已经审批，允许存在部分已收货数量
- 操作：采购人员填写原因并执行人工完成
- 结果：剩余未收货数量不再履约；已发生的收货、上架和库存事实保留；不补造剩余数量的库存流水；记录账号、会话和时间

### 场景 5：人工供需关联
- 操作：生产工单选择来源销售行，采购明细选择来源生产工单
- 结果：可查询关联，但系统不自动计算缺口、生成工单或采购建议

### 场景 6：采购人工完成后继续处置已收货货物
- 前置：采购订单部分收货，实际接收数量已经进入质量隔离位，允许存在待检、质检合格或质检不合格数量
- 操作：人工完成采购订单，再完成剩余采购到货质检；对合格数量放行并继续上架，对不合格数量执行退回或报废
- 结果：尚未收货数量终止；合格货物正常上架；报废货物生成原因和库存减少流水；历史收货事实不变

### 场景 7：盘点确认并调整
- 前置：盘点单为未盘点，盘点范围内存在库存余额
- 操作：开始盘点、录入实盘数量与差异原因、确认并调整
- 结果：状态依次变化；存在差异时只生成一次调整流水，无差异时不产生数量变化

## 自动化验收
- 重复到货验收、收货、质量检验、质量决定、质量执行、上架、直接拣货、异常释放或发货不重复产生业务或库存事实
- 到货数量不满足 `arrived_qty = rejected_qty + received_qty`、质检数量不满足 `inspected_qty = qualified_qty + unqualified_qty`、拒收缺少原因或本次到货超过当前待收数量时，整次命令失败且不产生部分事实
- 两个并发直接拣货请求中的自动预留不能使 `available_qty < 0`
- 上架不重复增加总库存，拣货不提前扣减总库存
- 发货数量不能超过有效预留和发货暂存位数量
- 释放预留不能超过 `reserved_qty - picked_qty`，退回拣货不能超过 `picked_qty - shipped_qty`
- 每次拣货和退回后，来源与目标库位均满足 `available_qty = on_hand_qty - reserved_qty >= 0`，有效预留分配合计保持不变
- 发货后，发货暂存位的实物与有效预留分配同步减少，业务预留的已释放数量增加
- 分批直接拣货中的自动预留、拣货和发货累计数量不得超过销售订单行允许履约数量
- 人工完成接口重复调用命中幂等结果，不得重复释放预留或追加业务事实
- 同一幂等键使用不同业务载荷时返回冲突，不得产生新的库存事实
- 库存余额可由有效流水和预留核对
- 跨租户库存、预留、单据和来源关联不可见
