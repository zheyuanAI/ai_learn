# MES API 契约

## 实现状态声明

本文列出的接口是一期可执行契约。当前 `platform-core` 已提供 MES 主数据、工单、派工、工序执行、领退料、报工、质检和成品入库的 Controller、应用服务、持久化适配器与自动化测试；统一认证上下文、权限、租户隔离和 `ApiResponse` 由共享安全链路负责。

S5 的关键生产写入仍以应用端口为唯一入口，库存变化不允许由 MES 直接操作库存表。历史设计说明中的“仅有 `/internal/ping`”是实施前状态，不代表当前实现。

## 通用目标约束

- 业务接口通过 Gateway 暴露，`tenant_id` 来自受信任的登录上下文，不接收客户端自行指定租户。
- 写接口目标上要求 `Authorization`；会产生业务事实或库存变化的命令还要求 `Idempotency-Key`。
- 相同租户、相同接口语义与相同 `Idempotency-Key` 的重复命令必须返回一致业务结果，不得重复产生工序执行、领退料或成品入库事实。
- 响应结构为 `code`、`message`、`data`、`request_id`，由现有 `ApiResponse` 统一包装。
- 所有关联对象必须属于当前租户。

## 主数据目标接口

- `POST /api/boms`
- `GET /api/boms`
- `POST /api/routings`
- `GET /api/routings`

### POST /api/boms

- 必填：`bom_code`、`product_id`、`version`、`components`
- `components[*]` 必填：`component_product_id`、`component_qty`、`uom`

### POST /api/routings

- 必填：`routing_code`、`product_id`、`version`、`operations`
- `operations[*]` 必填：`operation_no`、`operation_name`、`work_center_id`

## WorkOrder 目标接口

- `POST /api/work-orders`
- `PUT /api/work-orders/{id}`
- `GET /api/work-orders`
- `GET /api/work-orders/{id}`
- `POST /api/work-orders/{id}/submit`
- `POST /api/work-orders/{id}/approve`
- `POST /api/work-orders/{id}/reject`
- `POST /api/work-orders/{id}/complete`
- `POST /api/work-orders/{id}/manual-complete`

### POST /api/work-orders

- 必填：`product_id`、`planned_qty`、`planned_start_time`、`planned_finish_time`、`bom_id`、`routing_id`
- 可选：`source_sales_order_line_id`
- 语义：创建 `Draft`（未提交）的生产意图；一个工单最多关联一条销售订单明细，同一销售明细允许拆分到多个工单。
- 页面建议：选择销售明细后默认带出尚未被其他有效工单承接的数量，用户仍可修改；不触发 MRP 或自动排产。

### PUT /api/work-orders/{id}

- 前置：工单为 `Draft` 或 `Rejected`。
- 语义：修改产品、数量、计划时间、BOM、Routing 和可选销售来源；其他状态拒绝修改。

### 提交与审核

- `submit`：仅允许 `Draft / Rejected -> PendingApproval`。
- `approve`：仅允许 `PendingApproval -> Released`；校验并锁定有效 BOM 与 Routing 版本。
- `reject`：仅允许 `PendingApproval -> Rejected`，必填 `rejection_reason`。
- 审核通过后才允许下达派工、领料和开始工序执行。

### POST /api/work-orders/{id}/complete

- 前置：必需工序、报工、质检和数量约束满足。
- 结果：工单进入 `Completed`；该操作不直接产生库存变化。
- 完成方式：`completion_type = Normal`。

### POST /api/work-orders/{id}/manual-complete

- 必填：`completion_reason`。
- 前置：工单为 `Released` 或 `InProgress`，不存在未完成的在途库存命令。
- 结果：终止剩余生产并进入 `Completed + Manual`；不补造领料、执行、报工、质检、入库或库存流水。
- 已领未使用原料仍须通过生产退料正常退回。

## DispatchOrder 目标接口

- `POST /api/dispatch-orders`
- `GET /api/dispatch-orders`
- `POST /api/dispatch-orders/{id}/release`

### POST /api/dispatch-orders

- 必填：`work_order_id`、`operation_id`、`operator_id`、`dispatch_qty`
- 可选：`device_id`
- 语义：创建派工安排，不代表工序已经开始。

### POST /api/dispatch-orders/{id}/release

- 前置：关联 WorkOrder 已下达，工序与工单路线一致。
- 结果：派工进入 `Released`，允许创建并开始 OperationExecution。

## OperationExecution 目标接口

- `POST /api/operation-executions`
- `GET /api/operation-executions`
- `POST /api/operation-executions/{id}/start`
- `POST /api/operation-executions/{id}/pause`
- `POST /api/operation-executions/{id}/resume`
- `POST /api/operation-executions/{id}/complete`

### POST /api/operation-executions

- 必填：`dispatch_order_id`
- 可选：`device_id`；未提供时沿用派工的可选设备安排，仍允许为空。
- 结果：创建 `NotStarted` 的一次工序执行实例。

### 状态操作

- `start`：仅允许 `NotStarted -> Running`，记录实际开始时间和操作人。
- `pause`：仅允许 `Running -> Paused`，记录暂停时间和原因。
- `resume`：仅允许 `Paused -> Running`，记录恢复时间。
- `complete`：仅允许 `Running -> Completed`，记录完成时间。
- 状态操作返回 `operation_execution_id`、`status`、对应实际时间和 `work_order_progress`。

## MaterialIssue / MaterialReturn 目标接口

- `POST /api/material-issues`
- `POST /api/material-issues/{id}/confirm`
- `POST /api/material-returns`
- `POST /api/material-returns/{id}/confirm`

### POST /api/material-issues

- 必填：`work_order_id`、`items`
- `items[*]` 必填：`product_id`、`warehouse_id`、`location_id`、`issue_qty`

### POST /api/material-issues/{id}/confirm

- 语义：通过库存应用服务确认生产领料并减少仓库库存。
- 结果：返回领料状态及库存业务标识或库存流水关联；库存不足时整体失败。

### POST /api/material-returns

- 必填：`work_order_id`、`items`
- `items[*]` 必填：`product_id`、`warehouse_id`、`location_id`、`return_qty`

### POST /api/material-returns/{id}/confirm

- 语义：通过库存应用服务确认生产退料并增加退回库位库存。
- 结果：返回退料状态及库存业务标识或库存流水关联。

## WorkReport / QualityInspection 目标接口

- `POST /api/work-reports`
- `GET /api/work-reports`
- `POST /api/quality-inspections`
- `POST /api/quality-inspections/{id}/submit`
- `GET /api/quality-inspections`

### POST /api/work-reports

- 必填：`operation_execution_id`、`report_time`、`qualified_qty`、`defect_qty`
- 可选：`remark`
- 约束：`report_qty = qualified_qty + defect_qty`，累计数量不得超过工单允许上限。
- 返回：`reported_summary`、`work_order_progress`。

### POST /api/quality-inspections

- 必填：`work_report_id`、`inspection_type`、`sample_qty`
- 结果：创建 `Draft` 的 QualityInspection。

### POST /api/quality-inspections/{id}/submit

- 必填：`qualified_qty`、`defect_qty`、`result`
- 前置：QualityInspection 为 `Draft`，提交后按结果进入 `Passed` 或 `Failed`。
- 返回：`inspection_result`、`finished_goods_receipt_allowed_qty`。

## FinishedGoodsReceipt 目标接口

- `POST /api/finished-goods-receipts`
- `POST /api/finished-goods-receipts/{id}/confirm`
- `GET /api/finished-goods-receipts`

### POST /api/finished-goods-receipts

- 必填：`work_order_id`、`receipt_qty`、`warehouse_id`、`location_id`
- 约束：`receipt_qty` 不得超过累计检验合格数量减累计已入库数量。

### POST /api/finished-goods-receipts/{id}/confirm

- 语义：通过库存应用服务确认成品入库并增加成品库存。
- 返回：`receipt_status`、`finished_goods_summary` 及库存业务标识或库存流水关联。

## 查询过滤

- 工单：`keyword`、`status`、`product_id`、`source_sales_order_line_id`、`planned_date_from`、`planned_date_to`
- 派工：`work_order_id`、`operation_id`、`operator_id`、`status`
- 工序执行：`work_order_id`、`operation_id`、`device_id`、`status`、`date_from`、`date_to`
- 报工：`work_order_id`、`operation_id`、`date_from`、`date_to`
- 质检：`work_order_id`、`result`

## 业务错误码

| 错误码 | 含义 |
| --- | --- |
| `MES_WO_001` | WorkOrder 当前状态不允许该操作 |
| `MES_WO_002` | WorkOrder 未下达，禁止下达派工或开始执行 |
| `MES_WO_003` | 累计报工数量超出工单允许上限 |
| `MES_WO_004` | 来源销售订单行不存在、已失效或不属于当前租户 |
| `MES_WO_005` | 工单审核拒绝缺少原因，或当前状态不允许修改/提交/审核 |
| `MES_DIS_001` | DispatchOrder 与工单、工序或派工数量不一致 |
| `MES_EXE_001` | OperationExecution 当前状态不允许开始、暂停、恢复或完成 |
| `MES_EXE_002` | OperationExecution 与派工、工单或工序关系不一致 |
| `MES_MAT_001` | 生产领料库存不足或库存确认失败 |
| `MES_MAT_002` | 生产退料数量不合法或超出可退范围 |
| `MES_QC_001` | 质检未通过，禁止对应数量直接成品入库 |
| `MES_FG_001` | 成品入库数量超出检验合格且尚未入库的数量 |
| `MES_TENANT_001` | 关联对象不属于当前租户 |

幂等重放命中时不返回业务失败；应返回第一次成功命令的业务结果。

## 一期不提供的接口

- WIP 库存、线边仓和工序间在制品转移接口。
- 自动 MRP、自动工单生成、产能日历、APS 和自动排产接口。
- 返工单、返工执行和重复质检流程接口。

## 阶段 2–7 后端正式契约冻结补充（2026-09-04）

本节以当前 `platform-core` Controller、DTO 和应用服务为准，覆盖本文前面的目标性描述；未列出的路由不作为正式接口。所有写接口要求 `Authorization`、`Idempotency-Key`，租户和审计字段由可信上下文提供；页面 DTO 的数量按 `BigDecimal` JSON 数字输出，时间使用 ISO-8601 `OffsetDateTime`。

### S5 正式路由

基础和生命周期：

- `GET /api/boms?page=1&size=20&keyword=&status=`、`GET /api/boms/{id}`、`POST /api/boms`
- `GET /api/routings?page=1&size=20&keyword=&status=`、`GET /api/routings/{id}`、`POST /api/routings`
- `GET /api/work-orders?page=1&size=20&keyword=&status=`、`GET /api/work-orders/{id}`、`POST /api/work-orders`、`PUT /api/work-orders/{id}`
- `POST /api/work-orders/{id}/submit`、`approve`、`reject`、`complete`、`manual-complete`

执行和生产事实：

- `GET/POST /api/dispatch-orders`、`GET /api/dispatch-orders/{id}`、`POST /api/dispatch-orders/{id}/release`、`start-processing`、`complete`
- `GET/POST /api/operation-executions`、`GET /api/operation-executions/{id}`、`POST /api/operation-executions/{id}/start`、`pause`、`resume`、`complete`
- `POST /api/material-issues`、`POST /api/material-issues/{id}/confirm`
- `POST /api/material-returns`、`POST /api/material-returns/{id}/confirm`
- `POST /api/work-reports`、`GET /api/work-reports?work_order_id={uuid}`、`GET /api/work-reports/{workOrderId}`
- `POST /api/quality-inspections`、`POST /api/quality-inspections/{id}/submit`、`POST /api/quality-inspections/{id}/close`、`GET /api/quality-inspections?work_order_id={uuid}`、`GET /api/quality-inspections/{workOrderId}`
- `POST /api/finished-goods-receipts`、`POST /api/finished-goods-receipts/{id}/confirm`、`GET /api/finished-goods-receipts?work_order_id={uuid}`、`GET /api/finished-goods-receipts/{workOrderId}`

列表分页响应统一为 `records,total,page,size,totalPages`；生产事实的报工、质检和成品入库查询按当前实现返回当前租户指定工单的 JSON 数组，不伪装成分页。

### 请求字段冻结

- BOM：`bomCode,productId,version,status,components[*]{componentProductId,componentQty,uom}`；Routing：`routingCode,productId,version,status,operations[*]{operationNo,operationName,workCenterId,standardTimeMinutes}`；工单：`workOrderNo,productId,plannedQty,plannedStartTime,plannedFinishTime,bomId,routingId,sourceSalesOrderLineId`。
- 派工请求的正式 JSON 字段为 `work_order_id,operation_id,operator_id,dispatch_qty,device_id`；工序执行请求为 `dispatch_order_id,work_order_id,operation_id,device_id`。两类请求同时保留 DTO 声明的 camelCase 反序列化别名，但响应契约以 `DispatchOrder`/`OperationExecution` 事实字段为准。
- 领料请求为 `issueNo,workOrderId,items[*]{productId,warehouseId,locationId,quantity},overageReason`；退料请求为 `returnNo,workOrderId,items[*]{productId,warehouseId,locationId,quantity}`。`overageReason` 只有在超过 BOM 预计用量时必填，并保存到新增 V8 列。
- 报工请求为 `reportNo,operationExecutionId,workOrderId,operationId,reportTime,qualifiedQty,defectQty,remark`，服务端计算 `reportQty=qualifiedQty+defectQty`；质检创建为 `inspectionNo,workReportId,inspectionType,sampleQty`，提交为 `qualifiedQty,defectQty,result`；关闭为 `disposition`。
- 成品入库创建为 `receiptNo,workOrderId,receiptQty,warehouseId,locationId`。所有客户端不可提交 `tenantId,createdBy,submittedBy,confirmedBy` 等可信审计字段。

### 状态、数量闸门和质量闭环

- 工单状态为 `Draft -> PendingApproval -> Released -> InProgress -> Completed`，驳回分支为 `PendingApproval -> Rejected -> PendingApproval`；`PUT` 只允许 `Draft/Rejected`，并使用版本 CAS。
- 派工状态为 `Draft/Released/Processing/Completed`；工序执行状态为 `NotStarted/Running/Paused/Completed`。派工的 `operationId` 必须属于工单冻结 Routing，按工单计划量累计派工不得超额；同一设备活动工序不允许产生歧义。
- 开始后续工序前，所有 Routing 前置工序必须已经 `Completed`；报工必须引用有效执行实例，累计报工不得超过对应派工数量，也不得超过工单计划量。
- 质检状态为 `Draft/Submitted/Passed/Failed/Closed`；`Failed` 只能通过 `ISOLATE`、`SCRAP` 或 `CLOSE` 关闭，关闭只记录质量处置，不直接移动库存。未关闭的 Failed/Draft/Submitted 质检会阻塞工单进度。
- 成品入库只允许使用累计已检验合格且尚未入库的数量；领料、退料和成品入库产生库存变化时只能调用 `InventoryCommandService`，不得直写余额或流水表。

超 BOM 领料的服务端规则为：按 BOM 组件数量乘工单计划量计算预计值，结合既有确认领料和当前单据累计计算；超额创建/确认均要求非空原因，确认还要求 `mes:material:overage`。缺原因或无权限返回 `MES_FACT_002`（422）。

### 响应、权限和错误

- 工单详情为 `WorkOrderLifecycle`；派工列表为 `DispatchPage`，执行列表为 `OperationExecutionPage`，均含 `records,total,page,size,totalPages`；生产写入返回对应事实，确认领料/退料/报工/质检/入库的汇总返回 `ProductionFactSummary{operation,factId,fact,quantity,inventoryTransactionIds}`。
- 角色权限入口冻结为 `mes:bom:view`、`mes:routing:view`、`mes:workorder:view/create/update/submit/approve/complete`、`mes:dispatch:manage`、`mes:execution:manage`、`mes:material:requisition/confirm/overage`、`mes:report:manage`、`mes:quality:inspect`、`mes:finished:receipt/confirm`。
- 稳定错误：`MES_DISPATCH_005/006` 分别表示工序不在冻结 Routing、累计派工超计划；`MES_OPERATION_004/005/006/007` 覆盖工单未下达、关联不一致、设备活动冲突、前置工序未完成；`MES_WO_003` 表示累计报工超限；`MES_MAT_001/002` 表示领料/退料库存或数量失败；`MES_QC_001`、`MES_FG_001` 表示质量阻塞或成品入库超合格上限；`MES_FACT_001/002` 表示状态或字段/数量失败；`MES_TENANT_001` 表示跨租户关联。HTTP 状态以错误枚举为准，主要为 409 或 422。
