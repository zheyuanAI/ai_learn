# MES 概览

## 一期目标

围绕黄金业务闭环建设轻量化制造执行能力，打通 BOM、简化工艺路线、生产工单、派工、工序执行、生产领退料、报工、质检与成品入库。

一期必须明确区分：

- `WorkOrder` 表达“生产什么、生产多少、为何生产”的业务意图，可由用户人工关联来源销售订单行。
- `DispatchOrder` 表达将工序、数量、人员和可选设备安排给执行方的派工安排。
- `OperationExecution` 表达某道工序的一次实际执行，记录开始、暂停、恢复、完成、人员、可选设备和实际时间。
- `MaterialIssue`、`MaterialReturn` 通过库存应用服务连接生产执行与仓库库存事实。
- `WorkReport`、`QualityInspection`、`FinishedGoodsReceipt` 分别记录报工、质量结果和合格成品入库事实。

## 关键场景

```text
来源销售订单行
  -> 人工创建并关联 WorkOrder
  -> 下达 WorkOrder
  -> 创建并下达 DispatchOrder
  -> MaterialIssue 确认，原料仓库库存减少
  -> OperationExecution 开始 / 暂停 / 恢复 / 完成
  -> WorkReport 记录合格数和不良数
  -> QualityInspection 记录检验结果
  -> FinishedGoodsReceipt 确认，合格成品库存增加
  -> 未使用原料可通过 MaterialReturn 确认退回仓库
```

来源销售订单行只用于来源说明、进度汇总和追溯。一期不根据销售需求自动计算工单数量，不实现 MRP、自动工单生成或自动采购建议。

## 领域边界

- Core 内的 manufacturing 模块管理生产意图、派工与执行事实。
- quality 模块管理质检事实。
- 生产领料、退料和成品入库必须调用库存应用服务，制造模块不得直接修改 `InventoryBalance`。
- 工序执行可选关联 IoT 设备；设备事实仍由 IoT 独立保存，MES 不复制遥测或告警作为第二套事实。

## 风险点

- 工单、派工和工序执行若混为一个状态，会失去计划与现场事实的区别。
- 领退料、报工、质检和成品入库若缺少数量约束，可能造成库存或工单进度重复累计。
- 设备关联不是工序开始的强制条件，不能因 IoT 或 Core 短时不可用而篡改另一领域已保存的事实。

## 一期明确不做

- WIP 库存与线边仓。
- 自动 MRP、APS、产能日历和自动排产。
- 返工单、返工状态机、重复质检和复杂质量处置。
- 复杂物料消耗、批次与序列号组合规则。
