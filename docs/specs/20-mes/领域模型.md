# MES 领域模型

## 统一术语

- `WorkOrder`（生产工单）：生产指定产品和数量的业务意图，可人工关联来源销售订单行，不代表工序已经执行。
- `DispatchOrder`（派工单）：将工单中的工序、数量、人员和可选设备安排给执行方的业务指令，不代表现场已经开始。
- `OperationExecution`（工序执行）：某道工序实际发生的一次运行实例，记录开始、暂停、恢复、完成和实际参与者。
- `MaterialIssue` / `MaterialReturn`（生产领料 / 生产退料）：连接制造与库存的业务单据，确认后分别形成仓库库存减少 / 增加事实。
- `WorkReport`（报工）：记录工序执行的合格数量、不良数量和报工时间。
- `QualityInspection`（质量检验）：记录报工数量的检验结果。
- `FinishedGoodsReceipt`（成品入库）：将已检验合格且尚未入库的数量转为成品库存。

## 核心实体

- 主数据：`Bom`、`Routing`、`Operation`
- 意图与安排：`WorkOrder`、`DispatchOrder`
- 执行与事实：`OperationExecution`、`MaterialIssue`、`MaterialReturn`、`WorkReport`、`QualityInspection`、`FinishedGoodsReceipt`

## 通用字段约束

- 领域实体必须带 `id`、`tenant_id`、`created_by`、`created_at`、`updated_by`、`updated_at`；只追加的事实记录可不要求修改人字段。
- 所有跨域关联必须属于同一租户。
- 所有实际执行类记录必须可追溯到 `work_order_id` 和 `operation_id`。
- 跨模块标识用于业务引用，不允许 manufacturing 模块直接修改 sales、inventory 或 IoT 模块数据。

## 实体字段

### Bom

- 表头：`bom_code`、`product_id`、`version`、`status`
- 明细：`component_product_id`、`component_qty`、`uom`、`scrap_rate`

### Routing / Operation

- 路线：`routing_code`、`product_id`、`version`、`status`
- 工序：`operation_no`、`operation_name`、`work_center_id`、`standard_time_minutes`

### WorkOrder

- 字段：`work_order_no`、`product_id`、`planned_qty`、`planned_start_time`、`planned_finish_time`、`bom_id`、`routing_id`、`status`
- 可选来源：`source_sales_order_line_id`
- 汇总字段：`reported_qty`、`qualified_qty`、`defect_qty`、`received_qty`
- 来源销售订单行由用户人工选择，只用于说明来源、汇总进度与追溯；不触发自动数量计算或计划运算。

### DispatchOrder

- 字段：`dispatch_no`、`work_order_id`、`operation_id`、`operator_id`、`dispatch_qty`、`status`
- 可选字段：`device_id`
- 派工只表达安排；`Released` 不得被当成现场已开始。

### OperationExecution

- 字段：`execution_no`、`dispatch_order_id`、`work_order_id`、`operation_id`、`operator_id`、`status`
- 可选字段：`device_id`
- 时间字段：`started_at`、`paused_at`、`resumed_at`、`completed_at`
- 一个记录表达一次实际执行；暂停后恢复仍属于同一次执行，不创建新的工单或派工单。

### MaterialIssue

- 表头：`issue_no`、`work_order_id`、`status`、`confirmed_at`
- 明细：`product_id`、`warehouse_id`、`location_id`、`issue_qty`
- 追溯：确认后保存库存应用服务返回的库存业务标识或流水关联。

### MaterialReturn

- 表头：`return_no`、`work_order_id`、`status`、`confirmed_at`
- 明细：`product_id`、`warehouse_id`、`location_id`、`return_qty`
- 追溯：确认后保存库存应用服务返回的库存业务标识或流水关联。

### WorkReport

- 字段：`report_no`、`operation_execution_id`、`work_order_id`、`operation_id`、`report_time`、`qualified_qty`、`defect_qty`、`remark`
- 派生数量：`report_qty = qualified_qty + defect_qty`

### QualityInspection

- 字段：`inspection_no`、`work_report_id`、`work_order_id`、`operation_id`、`inspection_type`、`sample_qty`、`qualified_qty`、`defect_qty`、`result`

### FinishedGoodsReceipt

- 字段：`receipt_no`、`work_order_id`、`receipt_qty`、`warehouse_id`、`location_id`、`status`、`confirmed_at`
- 追溯：确认后保存库存应用服务返回的库存业务标识或流水关联。

## 关键规则

1. 工单必须绑定产品、计划数量、计划完工时间、有效 BOM 与有效 Routing。
2. `source_sales_order_line_id` 可为空；填写时必须由用户显式选择且属于同一租户。
3. 工单未下达时不得下达派工，也不得开始工序执行。
4. 派工不产生实际执行事实；只有 `OperationExecution` 的状态操作记录实际开始、暂停、恢复和完成。
5. 工序执行可选关联设备，设备不存在或不可关联时不得伪造设备事实；不关联设备不阻止人工工序执行。
6. 生产领料确认必须通过库存应用服务减少仓库库存；库存不足时整个确认失败，不允许出现负可用库存。
7. 生产退料确认必须通过库存应用服务增加退回库位库存；一期不引入线边仓或 WIP 库存。
8. 报工数量等于合格数量加不良数量，累计报工不得超过工单允许的计划数量上限。
9. 质检失败时记录不良数量并阻止对应数量直接成品入库；一期不创建返工单。
10. 成品入库确认必须通过库存应用服务增加成品库存，数量不得超过累计检验合格数量减累计已入库数量。
11. 领料、退料和成品入库确认必须幂等；相同业务命令重复调用不得重复产生库存事实。

## 状态机

### WorkOrder

- `Draft -> Released -> InProgress -> Completed`
- `Released` 后才允许下达派工。
- 首次有效的 `OperationExecution.start` 后进入 `InProgress`。
- 只有必需工序已完成、数量约束满足且不存在待处理质量阻塞时才允许 `Completed`。

### DispatchOrder

- `Draft -> Released -> Processing -> Completed`
- 下达只表示安排生效；关联工序执行开始后进入 `Processing`，关联执行完成后才可进入 `Completed`。

### OperationExecution

- `NotStarted -> Running -> Paused -> Running -> Completed`
- 只有 `Running` 可暂停或完成，只有 `Paused` 可恢复。
- 每次状态操作必须记录实际时间和操作人，非法重复状态迁移必须被拒绝。

### MaterialIssue / MaterialReturn / FinishedGoodsReceipt

- `Draft -> Confirmed`
- `Confirmed` 后不得再次产生库存变化；更正流程一期不做。

### QualityInspection

- `Draft -> Submitted -> Passed`
- `Draft -> Submitted -> Failed`

## 一致性与追溯

- 工单可向上追溯人工关联的销售订单行，向下追溯领退料、派工、工序执行、报工、质检和成品入库。
- 库存数量变化以 Inventory 领域保存的库存流水为事实源，MES 只保存来源单据和返回关联。
- IoT 遥测、设备状态与告警以 IoT 领域为事实源；MES 只保存工序执行上的可选 `device_id`。
- 所有查询、写入和关联均按 `tenant_id` 隔离。

## 一期边界

- 不建立 `WipInventory`、线边仓或工序间在制品转移模型。
- 不建立 `CapacityCalendar`、APS 或自动排产模型。
- 不建立 `ReworkOrder`、返工状态机或重复质检链路。
