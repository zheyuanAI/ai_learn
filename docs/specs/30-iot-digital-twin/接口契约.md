# IoT 设备接入 API 契约

## 实现状态声明

本文列出的 HTTP 与 MQTT 契约是一期可执行契约。当前 `platform-iot` 已提供设备模型、设备、凭证、遥测、状态、告警和人工上下文接口，并由 PostgreSQL 端口保存 IoT 自有事实；MQTT 真实消费链已接入 Paho 异步客户端并复用统一遥测摄取服务。

真实 MQTT 消费由 `iot.mqtt.enabled` 条件开启，默认关闭；启用时必须通过运行环境注入 Broker、独立订阅账号、外部 Mosquitto `password_file`/`acl_file` 和持久化目录。历史设计说明中的“仅有 `/internal/ping`”是实施前状态，不代表当前实现。

## 通用目标约束

- 管理类 HTTP 接口通过 Gateway 暴露，查询自动按登录上下文过滤 `tenant_id`。
- HTTP 写接口目标上要求 `Authorization`；具体 Token 校验流程尚未在当前代码中实现。
- MQTT 设备接入必须使用归属该设备的有效凭证；Broker 用户名使用创建凭证返回的 `credential_reference`，密码为仅创建响应展示一次的明文 secret，IoT 服务订阅端使用独立只读账号。
- 设备模拟接口只用于演示与自动化测试环境，并复用与 MQTT 相同的校验、去重和保存逻辑。
- HTTP 响应结构为 `code`、`message`、`data`、`request_id`，由现有 `ApiResponse` 统一包装。

## DeviceProfile 目标接口

- `POST /api/device-profiles`
- `GET /api/device-profiles`
- `GET /api/device-profiles/{id}`
- `POST /api/device-alarm-rules`
- `GET /api/device-alarm-rules`

### POST /api/device-profiles

- 必填：`profile_code`、`profile_name`、`metrics`
- `metrics[*]` 必填：`metric_code`、`metric_name`、`value_type`
- `metrics[*]` 可选：`unit`、`required`
- 可选：`offline_timeout_seconds`，未提供时一期默认 60 秒
- 语义：定义设备类型及允许上报的指标；本接口不虚构尚未冻结的复杂告警算法。

### POST /api/device-alarm-rules

- 必填：`rule_code`、`device_profile_id`、`metric_code`、`operator`、`trigger_threshold`、`recovery_threshold`、`alarm_level`
- 可选：`device_id`；不提供时规则作用于设备模型范围
- 语义：一期只定义单指标阈值触发与恢复，不接受多指标组合表达式或可执行脚本

## Device 与凭证目标接口

- `POST /api/devices`
- `GET /api/devices`
- `GET /api/devices/{id}`
- `POST /api/devices/{id}/credentials`
- `POST /api/devices/{id}/credentials/{credentialId}/revoke`

### POST /api/devices

- 必填：`device_code`、`device_name`、`device_profile_id`、`protocol_type`
- 可选：`work_center_id`、`area_id`、`map_point_id`
- 约束：一期 `protocol_type` 只允许 `MQTT`。
- 语义：设备关联稳定的工作中心或区域，不直接把“当前工单”保存为设备主关系。

### POST /api/devices/{id}/credentials

- 语义：为当前租户的设备创建有效接入凭证。
- 返回：凭证业务标识、状态和后续接入所需的一次性结果；具体密文格式与 Broker 认证实现尚未冻结。
- 查询接口不得返回可直接复用的明文凭证。
- 凭证明文只在创建成功响应中返回一次；后续只能查看业务标识和状态。

### POST /api/devices/{id}/credentials/{credentialId}/revoke

- 语义：撤销设备凭证；撤销后的凭证不得继续用于 MQTT 接入。

## MQTT QoS 1 目标契约

### Topic

- 遥测 Topic：`devices/{credential_reference}/telemetry`；`credential_reference` 不是 `device_code`，用于让 Broker ACL 将设备限制在自身主题。
- 租户和设备身份由已认证设备凭证解析，不信任载荷中自行声明的 `tenant_id`。
- 一期不提供 Modbus TCP、OPC UA 或 Ditto Topic / 映射契约。

### 遥测消息

```json
{
  "message_id": "msg-000001",
  "sequence": 1,
  "ts": "2026-08-20T10:00:00Z",
  "metrics": [
    {
      "metric_code": "temperature",
      "metric_value": 42.5,
      "metric_unit": "C"
    }
  ]
}
```

- 必填：`ts`、`metrics`，以及 `message_id` 或 `sequence` 中至少一个。
- `metrics[*]` 必填：`metric_code`、`metric_value`。
- `metric_code` 必须在设备关联的 DeviceProfile 中允许。
- 同时提供 `message_id` 与 `sequence` 时，以 `device_id + message_id` 作为主去重键，并保留 `sequence` 用于审计。
- 仅提供 `sequence` 时，以 `device_id + sequence` 去重。
- 重复投递视为幂等成功：不得重复保存遥测、推进状态或产生告警。
- 同一去重键携带不同载荷时拒绝处理并记录冲突。
- 任一指标不存在、类型错误或缺少必填指标时拒绝整条消息，不保存其中的合法指标。
- 延迟消息仍保存；其设备时间早于当前快照来源时间时，不得倒退 DeviceStatus 或重放告警生命周期。

## 遥测与状态查询目标接口

- `GET /api/devices/{id}/telemetry`
- `GET /api/devices/{id}/status`

### GET /api/devices/{id}/telemetry

- 查询参数：`metric_code`、`date_from`、`date_to`、`limit`
- 返回：原始遥测事实，包含 `message_id/sequence`、`ts`、`received_at` 与指标值。

### GET /api/devices/{id}/status

- 返回：`online_status`、`running_status`、`alarm_status`、`last_seen_at`、`last_message_key`。
- DeviceStatus 是当前快照，不能替代遥测或告警历史查询。

## DeviceAlarm 目标接口

- `GET /api/device-alarms`
- `GET /api/device-alarms/{id}`
- `POST /api/device-alarms/{id}/ack`
- `PUT /api/device-alarms/{id}/business-context`

### GET /api/device-alarms

- 查询参数：`device_id`、`status`、`alarm_level`、`date_from`、`date_to`、`context_status`
- 返回：告警事实及可选的 `operation_execution_id`、`work_order_id` 业务上下文。

### POST /api/device-alarms/{id}/ack

- 必填：`ack_comment`
- 前置：告警处于 `Triggered` 或 `RecoveredUnacked`。
- 返回：`alarm_status`、`ack_user`、`acked_at`。
- 告警恢复由后续有效设备事实驱动，不由确认接口伪造；已恢复未确认告警确认后进入 `Recovered`。

### PUT /api/device-alarms/{id}/business-context

- 可选：`operation_execution_id`、`work_order_id`，至少提供一项。
- 语义：在自动判断延后或不可靠时，由授权用户人工补充或更正业务上下文。
- 结果：`context_source = Manual`、`context_status = Linked`。
- 该操作不得改写告警触发、确认、恢复时间或 IoT 原始事实。

## 测试模拟目标接口

- `POST /api/protocol-adapters/mqtt/simulate`

### 请求体

- 必填：`device_code`、`ts`、`metrics`，以及 `message_id` 或 `sequence` 中至少一项。
- 语义：只在演示与测试环境模拟 MQTT QoS 1 消息，必须走同一去重与事实保存链路。
- 返回：`accepted`、`duplicate`、`message_key`、`telemetry_ids`；重复消息返回 `duplicate = true` 而非业务失败。

## Core 故障时的接口语义

- MQTT 接收、DeviceTelemetry 保存、DeviceStatus 更新和 IoT 内部告警保存不得同步依赖 Core 成功响应。
- Core 不可用时，告警的 `context_status` 可以保持 `Pending`，已保存事实仍可通过 IoT 查询接口读取。
- Core 恢复后可由补链任务按指数退避重试，也允许授权用户调用业务上下文接口人工补充；IoT 只在租户、设备、时间和上下文关系均通过校验后更新告警关联字段。

## 业务错误码

| 错误码 | 含义 |
| --- | --- |
| `IOT_PROFILE_001` | DeviceProfile 不存在、已失效或指标未被模型允许 |
| `IOT_DEV_001` | Device 不存在、已禁用或不属于当前租户 |
| `IOT_DEV_002` | 协议类型不受一期支持；一期仅允许 MQTT |
| `IOT_CRED_001` | DeviceCredential 无效、已撤销或与设备不匹配 |
| `IOT_TLM_001` | 遥测消息格式或指标值校验失败 |
| `IOT_TLM_002` | 遥测缺少 `message_id` 与 `sequence`，无法建立去重键 |
| `IOT_TLM_003` | 同一设备去重键对应不同载荷 |
| `IOT_ALM_001` | DeviceAlarm 当前状态不允许确认或恢复 |
| `IOT_ALM_002` | 告警规则无效、指标不匹配或阈值配置不合法 |
| `IOT_CTX_001` | 告警业务上下文不存在、不一致或不属于当前租户 |
| `IOT_TENANT_001` | 设备、凭证或关联对象跨租户 |

QoS 1 相同载荷的重复投递不返回 `IOT_TLM_003`，而是按幂等成功处理。

## 一期不提供的接口

- Modbus TCP、OPC UA 和真实 PLC 接入接口。
- Eclipse Ditto Thing/Feature 映射与同步接口。
- 三维数字孪生、Cesium 和通用多协议适配接口。

## 阶段 2–7 后端正式契约冻结补充（2026-09-04）

本节以当前 `platform-iot` Controller、DTO 和应用服务为准，覆盖本文前面的目标性描述；未列路由不作为正式接口。HTTP 成功响应统一包装为 `{code,message,data,request_id,timestamp}`，分页响应字段为 `records,total,page,size`；租户和审计身份从可信上下文或设备凭证解析，客户端不能覆盖。

### 冻结 HTTP 路由

- `PATCH /api/devices/{id}/lifecycle`：请求 `{lifecycle_status}`，只允许设备身份 `Active/Disabled` 变更，必须带 `Idempotency-Key`，返回 `DeviceView`。
- `GET /api/devices/{id}/telemetry?metric_code=&date_from=&date_to=&limit=100`：返回原始 `TelemetryFact[]`；`limit` 为 1–200，时间为 ISO-8601 `OffsetDateTime`。
- `GET /api/devices/{id}/status`：返回 `DeviceStatus{tenantId,deviceId,onlineStatus,runningStatus,alarmStatus,lastSeenAt,lastMessageKey,sourceTimestamp}`，它是快照而不是历史事实。
- `POST /api/protocol-adapters/mqtt/simulate`：仅测试/演示能力启用时可用，请求 `{device_code,ts,message_id,sequence,metrics[*]{metric_code,metric_value,metric_unit}}`；服务端补租户、设备 ID、接收时间和 payload hash，返回 `TelemetryIngestionResult{accepted,duplicate,messageKey,telemetryIds,status}`。
- `GET /api/device-alarms?device_id=&status=&alarm_level=&date_from=&date_to=&context_status=&page=1&size=20`、`GET /api/device-alarms/{id}`：返回 `AlarmPageResult` 或 `AlarmView`。
- `POST /api/device-alarms/{id}/ack`：请求 `{ack_comment}`，必须带 `Idempotency-Key`，只允许 `Triggered/RecoveredUnacked` 确认，返回 `AlarmView`。
- `PUT /api/device-alarms/{id}/business-context`：请求 `{operation_execution_id,work_order_id}`，至少提供一项并带 `Idempotency-Key`，返回 `ContextLinkResult`。

`DeviceView` 的正式返回字段为 `id,device_code,device_name,device_profile_id,protocol_type,lifecycle_status,work_center_id,area_id,map_point_id,created_at,allowedActions`；设备状态和告警状态不嵌入设备主数据。模拟入口的环境开关为 `iot.telemetry.simulation.enabled`（默认关闭），可使用 Spring 环境变量 `IOT_TELEMETRY_SIMULATION_ENABLED=true` 临时启用。

### MQTT、去重和上下文补链

- 真实消费只接受 `devices/{credential_reference}/telemetry`，IoT 订阅过滤器固定为 `devices/+/telemetry`，QoS 默认 1；设备凭证由 Broker `password_file/acl_file` 校验，设备只可发布自身主题，IoT 使用独立只读订阅账号。
- `message_id` 优先形成 `device_id + message_id` 去重键，否则使用 `device_id + sequence`；同键同 payload 是 `duplicate=true` 的幂等成功，同键不同 payload 返回 `IOT_TLM_003`（409）。拒绝消息不保存任何部分指标。
- 告警事实先在 IoT 本地保存，再自动补链；Core 不可用时告警保持 `context_status=Pending`，补链任务进入 `Retry`，不会回滚告警事实。后台调度固定延迟默认为 5000ms，每轮最多扫描 16 个租户、每租户领取 50 条到期任务，退避上限 1 小时。
- 自动补链成功写入 `context_source=Automatic/context_status=Linked`；人工接口成功写入 `Manual/Linked`。补链只接受租户、设备、告警时间一致的唯一活动生产上下文，禁止客户端伪造生产标识。

### 状态、权限和错误

- 设备生命周期：`Active/Disabled`；告警：`Triggered -> Acked -> Recovered` 或 `Triggered -> RecoveredUnacked -> Recovered`；上下文任务：`Pending/Processing/Retry/Completed`。
- HTTP 权限入口：`iot:device:view/manage`、`iot:telemetry:view`、`iot:alarm:view/ack/context`、`iot:device:simulate`；后台补链不使用用户权限 Header。
- `IOT_DEV_001`（404）表示设备不可见，`IOT_DEV_002/IOT_PROFILE_001/IOT_ALM_002/IOT_TLM_001/IOT_TLM_002`（422）表示协议、模型、规则或消息校验失败，`IOT_TLM_003/IOT_IDEMP_001`（409）表示 payload/命令冲突，`IOT_TLM_004`（403）表示模拟入口关闭，`IOT_CTX_001`（422）表示人工上下文不一致，`IOT_CRED_001`（401）表示设备凭证无效。

### 运行时安全边界

仓库只保存配置入口和占位示例，不保存真实 MQTT 密码、生成的 `passwordfile`、`aclfile` 或 HMAC 密钥。实际文件创建、权限保护、Broker 启动和 QoS 1 实机验证以 `runtime/README.md` 为准；当前工作区未启动真实 Mosquitto。
