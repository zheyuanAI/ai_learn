# IoT 设备接入概览

设备模型、凭证、消息去重、在线状态、阈值告警和生产上下文的详细规则以 [设备接入与告警业务规则](./设备接入与告警业务规则.md) 为准。

## 一期目标

通过 MQTT QoS 1 接入模拟设备，建立设备模型、设备、凭证、遥测、状态和告警事实，为 MES 工序执行、二维地图、看板和跨域追溯提供可信设备数据。

一期必须明确区分：

- `DeviceProfile` 描述设备类型及允许上报的指标。
- `Device` 表达设备身份、启停状态和工作中心 / 生产区域关联。
- 设备凭证只用于验证设备接入身份，不承载业务状态。
- `DeviceTelemetry` 保存设备在指定时间上报的原始遥测事实。
- `DeviceStatus` 保存根据最新有效消息推导的在线、运行和最后通信快照。
- `DeviceAlarm` 保存具有触发、确认、恢复生命周期的告警事实。

遥测、状态和告警不得合并成一个万能设备记录，也不得互相替代。

## 关键场景

```text
创建设备模型
  -> 创建设备并配置凭证
  -> 设备关联工作中心或生产区域
  -> 模拟设备通过 MQTT QoS 1 上报消息
  -> 按 device_id + message_id/sequence 去重
  -> IoT 独立保存遥测事实
  -> 更新 DeviceStatus
  -> 根据已确认规则生成或恢复 DeviceAlarm
  -> 自动、延后或人工补充 OperationExecution / WorkOrder 上下文
  -> 地图、看板和追溯只读展示
```

工序执行可选关联设备。设备告警在产生时不要求 Core 必须可用；无法可靠判断生产上下文时，先保存告警，再延后或人工补充关联。

## 可靠性边界

- MQTT 一期使用 QoS 1，必须接受重复投递并通过 `device_id + message_id/sequence` 保证同一消息只生成一次事实。
- IoT 独立保存设备、凭证、遥测、状态和告警，不直接读写 Core 表。
- Core 暂时不可用时，已经接收并通过基本校验的遥测不得丢失，状态与告警处理不依赖同步写入 Core。
- Core 故障只允许使业务上下文保持待补充，不允许回滚或删除已保存的设备事实。

## 风险点

- 把 MQTT QoS 1 当成“只投递一次”会产生重复遥测、重复状态变化或重复告警。
- 将原始遥测覆盖为当前状态会失去审计与重算依据。
- 设备直接绑定当前工单会制造易失关系；一期优先关联工作中心或生产区域，由工序执行可选关联设备。
- 在保存告警前同步调用 Core 会把业务服务故障扩散到采集链路。

## 一期明确不做

- Modbus TCP、OPC UA 和真实 PLC 深度适配。
- Eclipse Ditto、三维数字孪生和 Cesium。
- 通用协议适配平台或多协议 `ProtocolAdapter`。
- 未经规格冻结的复杂告警算法；具体指标阈值和组合规则必须在实现前另行确认。
