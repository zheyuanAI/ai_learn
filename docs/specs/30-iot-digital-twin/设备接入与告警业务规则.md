# 设备接入与告警业务规则

> 状态：一期目标设计已确认  
> 确认日期：2026-08-27

## 1. 一期范围

- 一期只接入使用 `MQTT`（设备消息通信协议）的模拟设备。
- 不实现 Modbus TCP、OPC UA、真实 PLC 深度适配、通用协议平台或三维数字孪生。
- 设备数据服务独立于 Core（生产、库存等核心业务服务）；Core 暂时不可用时，已接收的有效设备事实不得丢失。

## 2. 设备模型与设备

- `DeviceProfile`（设备模型）：定义某类设备允许上报的指标、数据类型、单位和是否必填。
- `Device`（设备）：某台实际或模拟设备的唯一身份。
- 设备可以长期关联工作中心、生产区域和二维地图点位，但不直接保存“当前工单”。
- 某次生产使用了哪台设备由 MES 的工序执行记录保存。
- 有历史数据的设备只能停用，不能物理删除；停用后不得继续接入。

## 3. 设备凭证

- 每台设备使用独立凭证，凭证不得跨设备或跨租户复用。
- 明文凭证只在创建时展示一次，查询接口不得回显可直接使用的密钥。
- 凭证可以撤销并重新生成；撤销后立即禁止继续接入。

## 4. 三类设备事实

| 事实 | 释义 | 保存方式 |
| --- | --- | --- |
| `DeviceTelemetry`（设备遥测） | 温度、转速等原始上报值 | 只追加，不覆盖历史 |
| `DeviceStatus`（设备状态） | 当前在线、运行、告警和最后通信快照 | 由最新有效消息更新 |
| `DeviceAlarm`（设备告警） | 异常触发、确认和恢复历史 | 保留完整生命周期 |

三类事实不得合并成一个万能设备记录，也不得用当前状态覆盖原始遥测。

## 5. MQTT 消息与去重

- MQTT 使用 `QoS 1`（至少送达一次：消息可能重复，但不会无确认地丢弃）。
- 每条消息必须携带 `message_id`（消息编号）或 `sequence`（设备递增序号）至少一项。
- 去重键优先使用“设备标识 + 消息编号”，否则使用“设备标识 + 递增序号”。
- 相同去重键、相同载荷的重复消息按幂等成功处理，不重复保存遥测、推进状态或生成告警。
- 相同去重键但载荷不同属于冲突消息，必须拒绝并保留审计错误。
- 不同设备可以使用相同消息编号，不得跨设备错误去重。

## 6. 延迟、状态与异常消息

- 延迟到达的合法数据仍保存为原始遥测，但不得把当前设备状态倒退到过去。
- 设备超过可配置时间没有有效通信时进入离线；一期默认 60 秒，允许按设备模型调整。
- 设备运行状态由设备上报的标准值驱动：空闲、运行、停止；平台校验后更新快照。
- 指标不存在、类型错误、缺少去重标识、设备停用或凭证无效时，拒绝整条消息并记录原因，不保存部分指标。

## 7. 告警规则

- 一期只支持单指标阈值告警，例如温度大于上限或小于下限。
- 每条规则至少包含设备模型/设备范围、指标、比较方式、触发阈值、恢复阈值和告警等级。
- 同一设备、同一规则同时只保留一个活动告警；活动期间的重复异常不新建告警。
- 原告警恢复后再次满足触发条件时，创建新的告警事实。

告警过程支持：

```text
已触发 -> 已确认 -> 已恢复
已触发 -> 已恢复但未确认 -> 补充确认
```

- 人工确认记录确认人、时间和意见，但不能伪造设备恢复。
- 恢复由后续有效设备事实驱动；设备先恢复时仍必须保留未确认信息。

## 8. 地图展示状态

点位展示状态使用：正常、预警、告警、离线。同一设备同时满足多个状态时，显示优先级为：

```text
告警 > 离线 > 预警 > 正常
```

展示状态只用于可视化，不反向修改设备或生产状态。

## 9. 生产上下文

- 告警产生时，如果能够唯一确定该设备正在参与的工序执行，则自动关联工序执行和生产工单。
- 无法唯一判断、Core 不可用或关联不可靠时，先保存告警并标记“待补充”。
- 授权人员可以人工补充或更正业务上下文，但不得修改告警触发、确认、恢复时间或原始遥测。

## 10. 保存顺序与故障边界

1. 校验租户、设备、凭证、消息格式、指标和去重键。
2. 保存未重复的原始遥测。
3. 基于已保存事实更新当前状态并处理告警。
4. 自动、延后或人工补充生产上下文。

第 4 步失败不得回滚前面已经保存的 IoT 事实。
