# IoT 设备接入领域模型

## 统一术语

- `DeviceProfile`（设备模型）：定义一类设备及允许上报的指标，不代表某台实际设备。
- `Device`（设备）：具有唯一业务身份的实际或模拟设备，可关联工作中心或生产区域。
- `DeviceCredential`（设备凭证）：验证设备 MQTT 接入身份的凭据记录，与设备业务状态分离。
- `DeviceTelemetry`（设备遥测）：带设备、采集时间和消息标识的原始上报事实。
- `DeviceStatus`（设备状态）：由最新有效遥测或心跳推导的在线、运行和最后通信快照。
- `DeviceAlarm`（设备告警）：由设备事实触发并具有触发、确认、恢复生命周期的异常事实。

## 核心实体

- `DeviceProfile`
- `Device`
- `DeviceCredential`
- `DeviceTelemetry`
- `DeviceStatus`
- `DeviceAlarm`
- `DeviceAlarmRule`

`ProtocolAdapter`、Ditto Thing/Feature 和三维数字孪生模型不进入一期领域模型。

## 通用字段约束

- 领域实体必须带 `id`、`tenant_id`、`created_at`；可变实体还带 `updated_at`。
- 不同租户的设备模型、设备、凭证、遥测、状态和告警绝对隔离。
- IoT 与 Core 共用 PostgreSQL 12.1 实例的同一 `public` schema 时，仍通过表名前缀、服务访问边界和受控外键/软引用保持模块隔离，禁止 IoT 直接关联查询或修改 Core 表。

## 实体字段

### DeviceProfile

- 字段：`profile_code`、`profile_name`、`status`
- 指标定义：`metric_code`、`metric_name`、`value_type`、`unit`、`required`
- 规则：DeviceTelemetry 中的指标必须被关联 DeviceProfile 允许。
- 可选在线超时：`offline_timeout_seconds`，一期默认 60 秒并允许按设备模型调整。

### Device

- 字段：`device_code`、`device_name`、`device_profile_id`、`lifecycle_status`
- 协议字段：`protocol_type`，一期只允许 `MQTT`
- 位置与业务归属：`work_center_id`、`area_id`、`map_point_id`
- `work_center_id` 与 `area_id` 可选，用于稳定归属；设备不直接保存“当前工单”作为主关系。
- `lifecycle_status` 只表达设备是否允许接入，与 `DeviceStatus.online_status`、`running_status` 分离。
- 已产生遥测或告警历史的设备只能停用，不允许物理删除。

### DeviceCredential

- 字段：`device_id`、`credential_status`、`credential_reference`
- 规则：凭证必须归属唯一设备与租户；禁用或撤销后不得继续接入。
- 凭证密文格式、MQTT Broker 认证机制和轮换细节尚未在仓库中冻结，不在领域规格中虚构。

### DeviceTelemetry

- 标识：`device_id`、`message_id` 或 `sequence`
- 时间：`ts`（设备采集时间）、`received_at`（平台接收时间）
- 指标：`metric_code`、`metric_value`、`metric_unit`
- 原始遥测为只追加事实，不得因 DeviceStatus 更新而覆盖或删除。
- 同一 MQTT 消息包含多个指标时，每个指标记录携带同一消息去重标识；重复消息不得再次写入任何指标记录。

### DeviceStatus

- 字段：`device_id`、`online_status`、`running_status`、`alarm_status`、`last_seen_at`、`last_message_key`
- DeviceStatus 是当前快照，不替代 DeviceTelemetry 或 DeviceAlarm 历史。
- 只有已成功保存且未被判定为重复的有效消息才允许推进状态。

### DeviceAlarm

- 字段：`alarm_no`、`device_id`、`alarm_type`、`alarm_level`、`status`、`triggered_at`、`acked_at`、`recovered_at`、`ack_user_id`
- 可选业务上下文：`operation_execution_id`、`work_order_id`、`context_source`、`context_status`
- 业务上下文是对 Core 业务标识的软引用；如确需数据库级约束，也只能在统一 `public` schema 下按服务所有权受控建立外键，不改变告警本身的设备事实属性。
- `context_source` 区分自动判断与人工补充；自动判断不可靠或 Core 不可用时，`context_status` 保持待补充。

### DeviceAlarmRule

- 字段：`rule_code`、`device_profile_id`、可选 `device_id`、`metric_code`、`operator`、`trigger_threshold`、`recovery_threshold`、`alarm_level`、`status`
- 一期仅支持单指标阈值比较，不支持多指标组合、复杂抑制或机器学习告警算法。
- 同一设备、同一规则同时只允许存在一个活动告警；恢复后再次触发时创建新告警。

## 三类事实分离

| 类型 | 记录内容 | 是否覆盖 | 是否依赖 Core |
| --- | --- | --- | --- |
| DeviceTelemetry | 原始指标、设备时间、接收时间、消息标识 | 否，只追加 | 否 |
| DeviceStatus | 最新在线、运行、告警状态和最后通信时间 | 是，作为当前快照更新 | 否 |
| DeviceAlarm | 触发、确认、恢复及可选业务上下文 | 否，保留生命周期事实 | 否；上下文可延后 |

## MQTT QoS 1 去重规则

1. 每个消息必须提供 `message_id` 或 `sequence`，至少一项存在。
2. 提供 `message_id` 时，去重键为 `device_id + message_id`；否则使用 `device_id + sequence`。
3. 同一去重键的 QoS 1 重复投递视为幂等成功，不重复保存遥测、不推进状态、不重复触发或恢复告警。
4. 同一去重键携带不同业务载荷属于冲突消息，必须拒绝并保留可审计错误。
5. 不同设备可以使用相同 `message_id` 或 `sequence`，不得跨设备错误去重。

## 状态机

### 设备生命周期

- `Active <-> Disabled`
- `Disabled` 设备的凭证不得继续用于 MQTT 接入。

### 设备在线状态

- `Online <-> Offline`
- 超过设备模型配置的有效通信时间进入 `Offline`；一期默认 60 秒。

### 设备运行状态

- `Idle -> Running -> Stopped`
- 允许 `Stopped -> Running`；状态来源必须是已保存的有效设备事实。

### 告警

- `Triggered -> Acked -> Recovered`
- `Triggered -> RecoveredUnacked -> Recovered`
- `Triggered` 记录触发时间，`Acked` 记录确认人与确认时间，`Recovered` 记录恢复时间。
- 设备事实可以先恢复再由人员补充确认，此时先进入 `RecoveredUnacked`（已恢复但未确认）；确认后进入 `Recovered`。
- 非法重复确认必须被拒绝；消息级去重与告警生命周期去重是不同问题。

## 设备与生产上下文

- Device 优先关联 `work_center_id` 或 `area_id`，用于表达稳定归属。
- `OperationExecution.device_id` 由 Core 保存且为可选；IoT 不直接修改工序执行。
- 告警产生后可根据设备与未完成工序执行自动补充上下文，也允许人工补充或更正。
- 自动关联不可靠或 Core 暂时不可用时，先保留告警并标记上下文待补充，不得丢弃、回滚或伪造关联。

## 保存顺序与故障边界

1. 验证设备、凭证、租户、消息格式和去重键。
2. 未重复的消息先在 IoT 边界内保存 DeviceTelemetry。
3. 基于已保存事实更新 DeviceStatus，并按已确认规则保存 DeviceAlarm。
4. 生产业务上下文在事实保存后自动、延后或人工补充。
5. Core 故障不得阻止步骤 2 和 IoT 内可独立完成的步骤 3；恢复后再处理待补充上下文。

延迟消息仍保存为原始遥测，但设备时间早于当前快照来源时间时不得倒退当前状态或重放已经结束的告警生命周期。指标不存在、类型错误或缺少去重标识时拒绝整条消息，不保存部分指标。

## 一期边界

- 仅支持 MQTT QoS 1 模拟设备接入。
- 不建立 Modbus TCP、OPC UA 或通用多协议适配模型。
- 不集成 Eclipse Ditto，不建设三维数字孪生。
- 不在本规格中推断未冻结的告警阈值、离线时长和复杂组合算法。
