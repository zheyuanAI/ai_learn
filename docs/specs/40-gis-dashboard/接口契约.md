# 二维 GIS 与综合看板 API 契约

> 本文定义一期可执行接口。当前 Controller、应用服务和 Facts 适配器已实现；由于 S7 依赖真实事实源，缺少任一必需端口时按条件不装配业务 Controller。

## 通用约束

- 所有接口要求通过共享安全链路建立的 `Authorization` 上下文，并校验当前用户的租户上下文与查询权限
- 客户端不得通过参数指定或覆盖 `tenant_id`
- 除二维底图/点位展示配置外，本领域一期只提供查询；任何接口都不得修改源业务事实
- 查询通过对应领域应用服务获得数据，不允许跨模块直连表或建立第二套业务事实
- 所有响应返回 `request_id`、`generated_at`；时间范围查询同时返回实际生效的 `time_range`

## 二维地图目标接口

- `POST /api/site-maps`
- `GET /api/site-maps`
- `GET /api/site-map`
- `GET /api/site-map/points/{point_id}`
- `POST /api/site-map/points`

### `POST /api/site-maps`

- 必填：`map_code`、`map_name`、二维底图资源
- 语义：创建当前租户的二维地图配置；一个租户允许多张地图
- 坐标体系：点位统一使用 `x_percent`、`y_percent` 相对百分比

### `GET /api/site-map`

- 必填参数：`site_map_id`（也接受兼容别名 `siteMapId`）；可选参数：`entity_type`、`status`
- 返回：二维底图、当前用户可查看的仓库/生产区域/设备点位、告警标记、`generated_at`

### `GET /api/site-map/points/{point_id}`

- 返回：点位展示信息、源业务实体引用、状态摘要、来源更新时间与允许跳转的业务页面

### `POST /api/site-map/points`

- 要求：`Authorization`、`Idempotency-Key` 和点位配置权限
- 必填：`site_map_id`、`entity_type`、`entity_id`、`x_percent`、`y_percent`
- 可选：`rotation`、`linked_page`
- 语义：只维护当前租户的二维展示配置，不修改被引用实体的业务状态

## 综合看板目标接口

- `GET /api/dashboard/inventory`
- `GET /api/dashboard/fulfillment`
- `GET /api/dashboard/manufacturing`
- `GET /api/dashboard/quality`
- `GET /api/dashboard/device`
- `GET /api/dashboard/alarms`
- `GET /api/dashboard/traceability`

### 看板通用查询参数

- 可选：`time_range`，支持 `today`、`7d`、`30d`，未提供时默认 `today`
- 可选：`warehouse_id`、`production_area_id`、`device_id`
- 筛选值必须属于当前租户且在当前用户权限范围内

### 看板通用返回字段

- `summary_type`
- `metrics`
- `time_range`：实际生效的起止时间
- `source_summary`：参与聚合的领域来源摘要
- `generated_at`
- `stale`：源服务不可用但返回上次成功结果时为 `true`
- `stale_since`：陈旧结果原生成时间，仅在 `stale = true` 时返回

看板缓存新鲜窗口为 60 秒，陈旧回退窗口为 10 分钟；缓存键包含租户、权限指纹、摘要类型、时间范围和白名单筛选条件。

## 服务间事实边界

- Core 内部事实适配器只调用库存、采购、销售、制造和质量应用/仓储端口，不直连其他模块 Mapper 或跨服务表。
- IoT 事实通过 `/internal/s7/facts/**` 提供只读投影；调用必须携带 `X-Service-Name`、时效 `X-Service-Timestamp` 和 HMAC `X-Service-Signature`，不复用用户 JWT，也不接受用户权限 Header。
- `production_area` 来源在当前仓库中未确认可用，因此对应点位解析会保持不可见，不能伪造生产区域事实。

## 业务错误码

- `GIS_AUTH_001`：当前用户无地图或看板查询权限
- `GIS_TENANT_001`：筛选实体不属于当前租户或发生跨租户访问
- `GIS_QUERY_001`：统计时间范围不支持
- `GIS_QUERY_002`：源领域查询暂时不可用
- `GIS_POINT_001`：点位不存在或当前用户不可见

## 明确排除

- Cesium 三维场景、模型资源和三维状态同步接口放入二期

## 阶段 2–7 后端正式契约冻结补充（2026-09-04）

本节以当前 `platform-core` Controller、DTO 和 Facts 适配器为准，覆盖本文前面的目标性描述；未列出的路由不作为正式接口。响应统一使用 `{code,message,data,request_id,timestamp}`，时间分别按 DTO 标注使用 ISO-8601 `Instant` 或 `OffsetDateTime`。

### 追溯

正式入口为 `GET /api/traceability?entity_type={type}&entity_id={uuid}`，只接受这两个 snake_case 参数，不再接受 `entityType/entityId` 别名。`data` 为 `TraceabilityProjection{nodes,links,hidden_node_count,missing_sources,generated_at,source_updated_at,request_id,truncated}`。

追溯从真实销售、采购、库存、制造、质量和 IoT Facts 端口按 BFS 展开，当前租户和节点权限双重过滤；单次最多 256 次事实查询、256 个节点和 512 条关系，超限以 `truncated=true` 明确返回。缺失来源进入 `missing_sources`，环路只去重不无限递归，不创建万能关系表。

### 二维地图

正式路由为：`GET/POST /api/site-maps`、`GET /api/site-map?site_map_id={uuid}&entity_type=&status=`、`GET /api/site-maps/{siteMapId}/projection?entity_type=&status=`、`GET /api/site-map/points/{pointId}`、`POST /api/site-map/points`、`PUT /api/site-map/points/{pointId}`、`DELETE /api/site-map/points/{pointId}`。`siteMapId` 仅作为路径变量；查询参数只认 `site_map_id`，历史 `siteMapId` 查询别名已删除。

- 地图创建请求为 `mapCode,mapName,asset`；点位新增/更新请求为 `siteMapId,entityType,entityId,xPercent,yPercent,rotation,linkedPage`，租户由可信上下文取得，写操作带 `Idempotency-Key`。
- 地图投影返回 `site_map_id,map_code,map_name,background_type,storage_key,points,generated_at,request_id`；点位投影返回 `point_id,entity_type,entity_id,display_name,x_percent,y_percent,rotation,display_status,linked_page,source_updated_at,alarm_id,alarm_level,alarm_status,occurred_at`。
- 坐标范围为 0–100，rotation 为 -360–360；实体只允许已接入的仓库、生产区域或设备引用。更新沿用点位 ID，删除为 GIS 自有配置软删除，不修改源业务事实。

### 七类看板与异常中心

一期只提供以下七个摘要入口，不提供 `/api/dashboard/overview`：`GET /api/dashboard/inventory`、`/fulfillment`、`/manufacturing`、`/quality`、`/device`、`/alarms`、`/traceability`。统一查询参数为 `time_range=today|7d|30d`（默认 `today`）、`warehouse_id`、`production_area_id`、`device_id`；正式契约只使用 snake_case。返回 `DashboardSummaryProjection{summary_type,metrics,time_range,source_summary,generated_at,source_updated_at,stale,stale_since,request_id}`。

异常中心为 `GET /api/exception-center?time_range=&source=&severity=&page=1&size=20`，只读地从库存、制造和 IoT 告警三类 Facts 派生，返回 `ExceptionCenterPage{records,total,page,size,totalPages,generated_at,source_updated_at}`；记录字段为 `source,exception_type,severity,value,message,occurredAt`。异常中心不落第二份库存/生产/告警事实表。

### 权限、错误和运行边界

- 追溯权限为 `trace:chain:view` 或 `ai:trace:view`；地图为 `gis:map:view/manage`；看板按 `dashboard:view` 或对应 `dashboard:{inventory|fulfillment|manufacturing|quality|device|alarm|traceability}:view`；异常中心为 `dashboard:view` 或 `dashboard:exception:view`。
- `GIS_AUTH_001`（403）表示无权限，`GIS_TENANT_001/GIS_POINT_001`（404）表示跨租户或点位不可见，`GIS_QUERY_001`（422）表示参数/时间范围不合法，`GIS_QUERY_002`（503）表示事实源不可用。
- 看板缓存的新鲜窗口为 60 秒，陈旧回退窗口为 10 分钟；缓存键含租户、权限指纹、摘要类型、时间范围和白名单筛选。源事实不可用且无可用旧结果时返回受控错误，不填充伪造 0 值。
- `production_area` 在当前仓库中未确认存在可用 Facts 源；相关点位/指标不能因原型或计划描述而被写成已实现。
