# 二维 GIS 与综合看板概览

多地图、点位配置、状态优先级、七组看板摘要、刷新和来源故障的详细规则以 [二维地图与综合看板业务规则](./二维地图与综合看板业务规则.md) 为准。

## 一期目标

以受租户和权限约束的只读查询模型，展示厂区、仓库、生产区域、设备点位及跨域业务摘要，帮助用户定位库存、履约、制造、质量、设备、告警和追溯异常。

GIS 与看板只投影各业务领域已经形成的事实，不建立第二套业务事实，不承担库存、订单、工单、质检、设备、告警或追溯数据的写入与状态迁移。二维底图和点位坐标属于本领域自身的展示配置，可以独立维护，但不能复制源实体的业务状态。

## 一期关键场景

- 二维地图展示厂区、仓库、生产区域、设备点位和告警状态
- 从点位查看受权限约束的业务摘要，并跳转到对应业务详情
- 看板按统一时间范围展示库存、履约、制造、质量、设备、告警和追溯摘要
- 同一来源事实经地图与看板查询时，业务标识、状态和统计口径一致

## 当前实现状态

- `platform-core` 已提供条件装配的追溯、二维 GIS 和七类看板查询；追溯、看板必须具备全部 Facts 端口才暴露 Controller，不以零值或内存假数据伪装生产成功。
- GIS 自有地图/点位配置可使用 PostgreSQL V6 持久化；看板缓存为可丢弃投影，优先使用 PostgreSQL，缺少 JDBC 时仅用于 focused 测试的内存实现。
- IoT Facts 默认通过 Core↔IoT 内部 HMAC 只读接口接入，需在两端同时配置 `CORE_FACTS_IOT_ENABLED`、`CORE_FACTS_IOT_HMAC_SECRET` 和 `IOT_INTERNAL_S7_HMAC_SECRET`；未配置时 S7 保持不可用。

## 一期边界

- 地图与看板是查询入口，不直接修改任何业务数据
- 展示数据由对应领域应用服务提供，查询模型不得跨模块直连表或复制出新的事实来源
- 地图点位只表达展示位置和业务实体引用，不替代设备、仓库、生产区域等主数据
- 本领域 Controller 已实现，但仍只提供查询和 GIS 自有配置写入；不修改库存、订单、工单、质检、设备或告警事实。
