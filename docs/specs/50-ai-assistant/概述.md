# AI 助手概览

Open WebUI、硅基流动 DeepSeek V4 Flash、受控知识、流式问答、受控只读工具、回答依据和安全边界的详细规则以 [AI 助手业务规则](./AI助手业务规则.md) 为准。

## 一期目标

提供受认证、租户和用户权限约束的自然语言只读查询入口。Open WebUI 作为模型、知识和 Agent 工具编排平台，通过硅基流动调用 DeepSeek V4 Flash，结合受控项目知识与 WMS 实时查询工具完成多步分析；WMS 仍负责身份、权限、租户、业务事实、工具执行和审计。

## 一期关键场景

- 查询低库存、指定产品与仓库库存
- 查询销售订单、采购订单和生产工单进度
- 查询质量统计与设备告警
- 通过 `queryTrace` 查询黄金业务闭环的关键上下游关系
- 基于受控查询结果生成简单日报或告警解释
- 在回答与审计中展示来源、数据时间范围和工具调用摘要
- 解释业务对象当前状态、阻塞原因和下一步处理角色
- 查询当前用户有权查看的业务对象操作时间线，解释哪个账号通过哪个会话执行了什么动作
- 检索 `docs/ai-knowledge/` 中经过清单控制的项目术语、角色、流程、状态和异常处理知识
- 一个问题涉及多个角色时，以文字说明主责角色、协同角色和建议处理顺序，不生成页面跳转动作

## 安全边界

- AI 不是超级管理员，必须沿用当前认证用户的租户和数据权限
- AI 实际可调用范围取 `wms-ai-api-whitelist.yml`、当前用户实时 Spring Security 权限和本次请求可选限制的交集
- 唯一白名单按业务模块组织，以精确 `method + path` 登记现有业务查询接口；禁止通配路径和模型提供任意 URL
- Open WebUI 只读取 Gateway 从该 YAML 和下游 OpenAPI 生成的裁剪目录，WMS 不再为每个 AI 场景复制一套查询接口
- AI 不得创建、修改或删除业务数据，不得触发业务状态迁移
- 工具参数必须再次校验租户、权限、范围和数量限制；模型输出不能替代后端授权
- Open WebUI 的服务身份不能代替 WMS 用户身份；工具调用必须通过服务端短期上下文恢复原用户并重新校验当前有效会话和权限
- 本阶段不提供 AI 页面跳转按钮；模型只能用文本说明处理角色和建议顺序
- 当前已实现聊天、能力与会话查询、Open WebUI Provider、统一 YAML 白名单、Gateway 裁剪 OpenAPI、委托身份恢复及首批 36 个现有业务查询操作；旧 10 个 AI 专用工具仅在迁移联调期保留兜底
- Windows Open WebUI 的既有 `wms` Tool Server 需要在 Gateway、Core、IoT 重启后重新执行 `configure-windows.ps1`，切换为 `wms_core` 与 `wms_iot`；新链路自动化边界测试已通过，真实多角色端到端回归仍待执行
