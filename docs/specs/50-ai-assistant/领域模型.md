# AI 助手领域模型

## 核心实体

### `ChatSession`

- 字段：`id`、`tenant_id`、`session_no`、`user_id`、`question_count`、`last_message_at`、`created_at`、`updated_at`

### `ChatMessage`

- 字段：`id`、`tenant_id`、`session_id`、`role`、`content`、`source_summary`、`time_range_summary`、`tool_call_summary`、`navigation_action_summary`、`model_id`、`status`、`created_at`、`updated_at`
- 规则：助手回答必须同时保存来源摘要、数据时间范围摘要和工具调用摘要

### `ToolAuditLog`

- 字段：`id`、`tenant_id`、`user_id`、`session_id`、`request_id`、`tool_name`、`input_summary`、`output_summary`、`source_summary`、`time_range_summary`、`tool_call_summary`、`model_id`、`duration_ms`、`status`、`error_code`、`error_reason`、`created_at`、`updated_at`
- 规则：无论成功、失败、超时或拒绝，工具调用均须记录审计；摘要不得记录凭证或无关敏感数据

### `BusinessOperationAudit`

- Core、Auth、IoT 分别保存本服务拥有的操作审计；禁止多个服务共同写一张万能审计表
- 通用字段：`id`、`tenant_id`、`actor_type`、`actor_id`、`actor_account`、`session_id`、`request_id`、`action_code`、`entity_type`、`entity_id`、`entity_no`、`before_status`、`after_status`、`operation_summary`、`changed_fields_summary`、`result`、`error_code`、`error_reason`、`occurred_at`
- 幂等操作只保存 `idempotency_key_hash`，不得保存原始幂等键；相同成功操作重放不得重复生成成功审计
- 业务实体、库存流水、工序事件和设备事实仍是业务事实源；操作审计只解释账号、会话、动作和结果
- 企业共享账号时只能识别账号和会话，不能据此识别背后的自然人

### `PageContext`

- 字段：`entity_type`、`entity_id`、`entry_page_code`
- 规则：只允许页面传递明确业务对象标识，不允许携带 `tenant_id`、`user_id`、权限集合或整个页面状态

### `NavigationAction`（兼容保留、当前阶段停用）

- 字段：`action_code`、`label`、`entity_type`、`entity_id`、`reason`、`confirm_text`
- 规则：当前阶段响应固定不生成导航动作；该对象只为兼容已有代码和历史消息保留，重新启用必须另行评审

### `AiInvocationContext`

- 字段：`request_id`、`open_webui_chat_id`、`open_webui_message_id`、`tenant_id`、`user_id`、`session_id`、`allowed_tool_codes`、`expires_at`
- 规则：仅短期保存在服务端 Redis，用于把 Open WebUI 工具调用恢复为原 WMS 用户上下文；Open WebUI 标识只作为关联键，不能单独作为认证凭据

## 一期业务 API 工具目录

- 唯一事实源：`deploy/openwebui/wms-ai-api-whitelist.yml`
- 首批 36 个操作按主数据、销售、采购、库存、制造、看板、追溯审计和 IoT 分组
- 每个操作只登记稳定 `operation id`、所属服务、HTTP 方法、现有业务路径和模型可读摘要
- Gateway 将 Core/IoT 完整 OpenAPI 按该清单裁剪后提供给 Open WebUI；模型可自行组合多个现有业务查询接口生成诊断或日报
- 旧 10 个 AI 专用聚合工具处于迁移兼容期，不再作为新增能力的默认扩展方式；新链路验收后删除

## 关键规则

- 认证上下文由服务端提供；模型和客户端均不得声明或覆盖 `tenant_id`、`user_id` 和权限范围
- AI 复用现有业务 Controller 与 ApplicationService，不得直连表、拼接或执行 SQL、跨模块访问 Repository
- YAML 白名单是 AI 可调用业务 API 的唯一能力上限；Gateway 只接受精确 method + path，请求可选白名单只能继续缩小
- 查询结果必须按租户、数据权限、时间范围和数量上限过滤
- 回答只能基于本次已授权工具返回的事实；无法取得依据时必须明确说明无可用事实依据
- 回答和审计必须关联相同的 `request_id`，并保留来源、实际数据时间范围和工具调用摘要
- 目标架构由自托管 Open WebUI 管理 DeepSeek 模型预设、受控知识检索和多轮工具选择；实际模型编号由部署配置决定并写入审计
- Open WebUI、DeepSeek 基础地址、模型编号和密钥均来自服务端安全配置；客户端不得覆盖，密钥不得写入会话或审计
- Open WebUI 只绑定 `docs/ai-knowledge/` 清单内知识和 Gateway 发布的裁剪业务 OpenAPI，不注册联网搜索、Shell、代码执行、文件系统、通用 HTTP 或任何写工具
- 工具调用必须同时验证 Open WebUI 服务身份、WMS 短期调用上下文和当前有效 `jti`；下游现有 Spring Security 再按恢复后的用户、租户和实时权限完成最终授权
- 工具调用状态：`Success`、`Failed`、`Timeout`、`Denied`

## 知识边界

- 当前阶段使用 Open WebUI 管理知识索引，WMS 不新增 `KnowledgeDocument`、`KnowledgeChunk` 业务表
- MinIO 与 WMS 自建 pgvector 不作为当前阶段依赖
- 正式业务规格仍是事实源，`docs/ai-knowledge/` 只是经过清单控制的模型知识视图
