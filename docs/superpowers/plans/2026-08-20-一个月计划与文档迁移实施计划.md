# 一个月计划与文档迁移实施计划

> **供代理执行：** 必须使用 `subagent-driven-development`（推荐）或 `executing-plans` 按任务执行；每一步使用复选框跟踪。

> **状态口径：** 本计划保留执行步骤清单；任务完成状态以 `.superpowers/sdd/2026-08-20-一个月计划与文档迁移实施计划/progress.md` 为准。

**目标：** 将当前项目交付周期统一为一个月，把领域规格和 OpenSpec 迁入 `docs/`，并在不改变业务行为、构建与运行约定的前提下尽可能采用中文文档文件名；允许为修正文档展示路径而同步更新前端 `specPath` 元数据。

**实施方式：** 先迁移长期领域规格并建立新事实源，再迁移 OpenSpec 协作入口，随后更新所有当前生效引用和历史计划标识。每个目录迁移都在下一步开始前验证文件数量、旧入口清理和引用完整性，避免一次性移动后无法判断断链来源。

**技术栈：** Markdown、YAML、Git 工作区、PowerShell、ripgrep；业务代码、Java/Maven、Node/Vite 和运行配置不做功能性修改，仅允许修正前端路由中的文档路径元数据。

## 全局约束

- 当前正式开发周期为一个月、四周；十周计划只保留为历史学习计划。
- 一期目标是黄金业务闭环可运行、可演示、可验收；GIS、看板和 AI 仅做轻量只读能力。
- `specs/` 迁移为 `docs/specs/`，并继续作为长期领域规格事实源。
- `openspec/` 迁移为 `docs/openspec/`，仅显式以 `OpenSpec` 或 `openspec` 开头的任务才读取其入口。
- 业务说明文档优先采用中文文件名；代码、配置、构建、运行和工具固定约定文件保持原名。
- 不修改参考工程、编译产物和历史审查快照；仅同步本次迁移对应的 `.superpowers/sdd/**` 任务报告与进度账本事实，不改历史差异文件。
- 保留工作区内用户和其他代理已有改动，不批量格式化、不覆盖无关内容。
- AI 不执行 Git commit；所有改动留给用户审核和提交。
