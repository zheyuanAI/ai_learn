# 架构思考卡实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在工作区级 `docs/` 中生成一份可跨项目、跨 AI 使用的独立架构思考卡。

**Architecture:** 使用单一 Markdown 同时承载 AI 对话协议、按需启用的八维问题卡、用户决策输入、AI 评审输出、小型决策记录、启动提示词和通用示例。文档不引用当前 WMS 项目的业务事实或技术栈，复制到其他项目后无需改写正文。

**Tech Stack:** Markdown、PowerShell、ripgrep

## Global Constraints

- 目标文件固定为工作区级 `docs/架构思考卡.md`。
- 普通功能点的基础判断应能在 5～15 分钟内完成。
- AI 必须先解释再提问，用户作出判断前不得替用户选择方案。
- AI 必须区分事实、假设和未知，每轮只提出一个关键问题。
- AI 评审结论必须为“可落地”“补充后落地”或“暂不建议落地”之一。
- 最终文件不得引用当前仓库专属事实、业务术语或技术栈。
- 按仓库 `AGENTS.md` 约束，不执行 Git Commit。

### Task 1: 生成并验证架构思考卡

**Files:**
- Create: `docs/架构思考卡.md`
- Modify: `docs/superpowers/specs/2026-08-21-架构思考卡设计.md`

**Interfaces:**
- Consumes: 已批准的设计规格及其八个思考维度、AI 行为约束和完成标准。
- Produces: 可直接阅读、复制和交给其他 AI 执行的单文件 Markdown。

- [x] **Step 1: 编写使用目标和 AI 对话协议**

  写明适用范围、非目标和固定流程：“上下文核对 → AI 解释 → AI 单题提问 → 用户判断 → AI 评审 → 决策留档”。明确事实、假设、未知三类标签，以及 AI 在用户判断前保持方案中立的要求。

- [x] **Step 2: 编写八维按需思考卡**

  为“业务与不变量、边界与所有权、模型与状态、流程与补偿、数据风险、质量属性、方案权衡、未来演进”八个维度提供精简问题。每个问题必须能帮助作出具体决定；跨模块写入、状态迁移、并发竞争、重复请求、异步消息和外部依赖必须有对应深入触发条件。

- [x] **Step 3: 编写输入输出模板**

  加入用户决策模板、AI 评审模板和小型架构决策记录模板。用户模板必须包含选择、理由、事实、假设、代价和重新设计条件；AI 模板必须包含结论、成立之处、关键风险、遗漏、过度设计检查和验证建议。

- [x] **Step 4: 编写可复制启动提示词和通用示例**

  启动提示词必须在脱离当前仓库后仍能约束其他 AI 按协议工作。示例使用“文件导出任务采用同步还是异步处理”这一通用问题，展示 AI 解释、用户判断和 AI 评审，不把任一方案表述为无条件正确答案。

- [x] **Step 5: 标记设计规格为已批准**

  将设计规格中的 `**状态：** 待用户审阅` 更新为 `**状态：** 已批准（用户于 2026-08-21 批准）`，不改写其他已确认内容。

- [x] **Step 6: 执行结构与独立性验证**

  Run:

  ```powershell
  rg -n '^## ' 'docs/架构思考卡.md'
  rg -n '事实|假设|未知|可落地|补充后落地|暂不建议落地|重新设计' 'docs/架构思考卡.md'
  rg -n 'WMS|仓储|库存|Spring|Vue|PostgreSQL|ai_learn' 'docs/架构思考卡.md'
  ```

  Expected: 第一条列出所有约定章节；第二条覆盖全部关键协议词；第三条无输出且退出码为 1，证明正文未绑定当前项目。

- [x] **Step 7: 人工内容自检**

  逐项确认：无占位标记或待补内容；示例遵守先解释后判断再评审；所有模板字段与对话协议一致；普通功能点无需遍历全部八维；全文可作为一个独立文件使用。

- [x] **Step 8: 保留改动供用户审核**

  不执行 `git add` 或 `git commit`。向用户提供目标文档和设计规格的可点击路径，以及实际验证结果。
