# 销售订单高保真原型 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本仓库 `AGENTS.md` 禁止直接 Git Commit，因此计划中的每批改动只验证、不提交。

**Goal:** 将已冻结的销售订单双轴状态和分批履约规则实现为可点击、响应式、可验证的高保真静态原型。

**Architecture:** 保留 `docs/prototype/assets/app.js` 的共享导航职责，销售交付页使用独立 `sales-outbound.js` 管理浏览器内假数据、角色、场景、动作弹窗和时间线。页面样式使用 `sales-*` 命名空间追加到共享 CSS，避免影响其他原型页。

**Tech Stack:** 语义化 HTML5、原生 CSS、原生 JavaScript、静态 HTTP 服务、Playwright 浏览器验证。

### Task 2: 实现派生状态和数量规则

**Files:**
- Create: `docs/prototype/assets/sales-outbound.js`

- [x] **Step 1: 定义三个评审场景**

每个场景都包含 `status`、`completionType`、`lines`、`events`。至少覆盖：

```js
const salesScenarios = {
  partial: { status: "Approved", completionType: null },
  manual: { status: "Completed", completionType: "Manual" },
  normal: { status: "Completed", completionType: "Normal" }
};
```

- [x] **Step 2: 实现唯一数量派生入口**

```js
function deriveLineProgress(line) {
  return {
    unreservedQty: line.orderedQty - line.reservedQty,
    unpickedQty: line.reservedQty - line.pickedQty,
    shippingStagedQty: line.pickedQty - line.shippedQty,
    activeReservedQty: line.reservedQty - line.shippedQty,
    unshippedQty: line.orderedQty - line.shippedQty
  };
}
```

- [x] **Step 3: 实现动态履约状态**

```js
function deriveFulfillmentStatus(lines) {
  if (lines.every((line) => line.shippedQty === line.orderedQty)) return "FullyShipped";
  if (lines.every((line) => line.reservedQty === 0 && line.pickedQty === 0 && line.shippedQty === 0)) return "NotStarted";
  return "InProgress";
}
```

- [x] **Step 4: 实现数量不变量检查**

```js
function isLineQuantityValid(line) {
  return 0 <= line.shippedQty
    && line.shippedQty <= line.pickedQty
    && line.pickedQty <= line.reservedQty
    && line.reservedQty <= line.orderedQty;
}
```
