# 采购拒收与黄金闭环角色拆分 Implementation Plan

> **后续变更：** 本计划保留为历史实施记录。其中“仓库收货时同时填写合格数量与质量隔离数量”的旧模型，已被同日的《销售直接拣货与采购先隔离后质检 Implementation Plan》替代；当前业务事实以 `docs/specs/` 正式规格为准。

> **For agentic workers:** 按当前会话内联执行；本仓库禁止 AI Git Commit。步骤使用复选框记录完成情况。

**Goal:** 支持采购货物在收货确认前全部或部分拒收，并将业务架构黄金闭环从模块级角色改为节点级角色，准确区分采购、仓库和生产质检职责。

**Architecture:** 采购到货仍复用 `PurchaseReceipt（采购收货单）`，用到货、拒收、接收、合格和质量隔离数量表达一次验收结果；只有接收数量进入企业库存，拒收数量保留到货拒收事实并继续作为采购待收数量。黄金闭环节点直接保存自己的角色、输入、输出、状态和异常，渲染器不再用模块全部角色代替节点执行角色。

**Tech Stack:** Markdown 业务规格、原生 JavaScript 数据驱动渲染、静态 HTML、Playwright。
