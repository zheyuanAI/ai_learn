# 业务架构空间与销售业务架构图设计

> 状态：已批准；2026-08-27 已同步全模块确认规则  
> 日期：2026-08-27  
> 事实来源：`docs/specs/` 正式规格与库存、销售、采购、生产质检、IoT、GIS 看板、AI 助手的已确认一期规则  
> 说明：业务架构 HTML 是业务沟通与导航工件，不表示对应后端接口已经实现。

## 1. 目标

在 `docs/业务架构/` 建立独立的业务架构浏览空间，使用户打开主入口后可以：

- 通过预览页快速了解项目范围、模块成熟度并进入目标页面；
- 通过总览页查看一期黄金业务闭环、模块关系、事实流和服务边界；
- 进入销售、采购、库存、制造质量、IoT、GIS/看板和 AI 等模块架构页；
- 在模块页查看业务目的、主链路、角色、状态、模块边界、异常和扩展点；
- 从任意业务架构页通过右上角小型入口跳转到 `docs/prototype/index.html`；
- 从任意原型页通过右上角小型入口跳转到 `docs/业务架构/index.html`。

业务架构与操作原型只在空间主入口之间跳转，不建立模块级页面映射，不传递查询参数，也不记忆上次访问位置。

## 2. 信息可信度

- 七个业务模块均使用对应 `docs/specs/` 正式业务规则、领域模型、接口契约和验收标准，统一标记为“已确认”。
- 仓库内未定义的接口、状态、算法或异常规则不得补写为既有事实。
- 页面持续显示“目标设计 / 接口未实现”说明，防止将架构图误认为实际能力。

```text

│  ├─ 销售业务架构.html
```

## 4. 空间切换

业务架构页右上角显示小型普通链接：

```text
操作原型 ↗
```

目标固定为 `../prototype/index.html`。原型空间右上角显示：

```text
业务架构 ↗
```

- `docs/prototype/index.html` 指向 `../业务架构/index.html`；
- `docs/prototype/pages/*.html` 指向 `../../业务架构/index.html`。

链接面积满足可识别与键盘访问要求，但不使用大型按钮，不抢占页面主标题视觉层级。

## 5. 预览页与总体业务架构页

### 5.1 业务架构预览页

`docs/业务架构/index.html` 是业务架构空间主入口，页面标题标识为“业务架构预览”。它承担快速理解和导航职责，包含：

1. 项目定位、一期范围与目标设计说明；
2. 总体业务架构入口；
3. 各模块的目的、成熟度、事实来源和页面入口卡片；
4. “七模块规则已确认、等待整体复核”的阶段状态；
5. 一期能力、未来候选和接口实现状态摘要；
6. 最近完成与下一步评审提示。

预览页不展开复杂跨模块连线，也不承载完整黄金闭环细节。

### 5.2 总体业务架构总览页

`docs/业务架构/总览.html` 页面标题标识为“总体业务架构总览”，专门说明模块之间的关联关系、流程和事实边界，包含五个可切换视图：

1. **模块拓扑**：Frontend、Gateway、Auth、Core、IoT 四个物理服务及 Core 内部逻辑模块关系；
2. **黄金闭环**：销售需求、人工供需关联、采购入库、生产执行、成品入库、销售出库和追溯的端到端流程；
3. **事实流**：业务意图、执行单据、库存事实、制造事实、设备事实和只读投影之间的数据方向；
4. **职责边界**：每个模块拥有的事实、允许调用的应用服务和禁止直接修改的对象；
5. **一期与扩展**：一期已确认能力、当前实施路线和二期候选。

总览页中的模块节点可进入对应模块业务架构页；点击流程节点后，在侧边详情区展示角色、输入、输出、状态、异常和事实来源。

预览页和总览页都不得把财务、MRP、APS、三维数字孪生或写业务数据的 AI 表述为一期能力。

### 5.3 业务架构空间内部导航

所有业务架构页面顶部保留轻量内部导航：

```text
预览 ｜ 总览 ｜ 当前模块
```

内部导航与右上角“操作原型”空间切换职责分离：前者在业务架构空间内浏览，后者始终跳转到原型主入口。

## 6. 模块业务架构页

所有模块页面共享一致的信息骨架：

1. 模块目的与当前成熟度；
2. 业务输入、主流程和业务输出；
3. 上下游模块关系；
4. 本模块拥有的事实；
5. 不允许越过的模块边界；
6. 核心角色与关键状态；
7. 一期异常控制；
8. 未来扩展点；
9. 相关正式规格链接；
10. 返回总体业务架构和前往操作原型的入口。

### 6.1 销售模块

销售页需要完整表达：

- 客户需求进入销售订单；
- `Draft -> Submitted -> Approved -> Completed` 生命周期；
- `NotStarted / InProgress / FullyShipped` 动态履约进度；
- 页面正常路径为“审核通过 -> 分批直接拣货 -> 分批发货”，直接拣货在同一事务内自动预留本次数量；退回拣货和释放未拣预留只作为异常处理；
- 全部发货进入 `Completed + Normal`；
- 终止剩余履约进入 `Completed + Manual`；
- 销售与库存、生产、采购、Auth、追溯/看板/AI 的关系；
- 数量不变量、幂等、并发、库位分配、租户和人工完成前置；
- 当前一期终点及退货、财务、ATP/MRP、物流等未来扩展。

### 6.2 其他模块

采购、库存、制造质量、IoT、GIS/看板和 AI 页面展示正式规格中的已确认一期链路。页面标记“已确认”，同时持续显示“目标设计 / 接口未实现”，不得把业务确认误写成代码已经实现。

## 7. 交互

- 顶部提供总览、业务链、模块关系、异常、扩展和实施路线等视图切换；
- 预览页只负责导航和成熟度摘要，总览页承担跨模块图形与流程交互；
- 点击流程节点后，在同页详情区展示职责、状态、输入输出、边界与异常；
- 模块卡可进入独立模块页；
- 支持键盘操作、焦点可见和窄屏布局；
- 无外部网络依赖，不使用 Canvas 绘制文字，不依赖构建工具；
- 所有交互只改变浏览器内视图，不声称调用业务接口。

## 8. 视觉

- 延续现有深色工业管理端，但业务架构空间使用独立命名空间；
- 主链使用清晰的方向、阶段编号和模块色标；
- 已确认、等待整体复核、一期边界和未来扩展使用不同但克制的状态标识；
- 首屏优先说明整体链路，细节通过点击展开，避免一张超宽图塞入全部文本；
- 右上角空间切换链接保持小型、普通、可识别。

## 9. 数据与实现方式

业务架构页采用数据驱动渲染：

- `business-architecture-data.js` 保存模块、流程节点和关系说明；
- `business-architecture.js` 只负责筛选、节点详情、视图切换和可访问性；
- 每个 HTML 只定义页面语义骨架与当前模块编码；
- `business-architecture.css` 使用 `biz-*` 命名空间，避免影响原型样式。

业务架构数据不是后端业务数据，也不与原型假数据共享状态。

## 10. 验收

- `docs/业务架构/index.html` 可直接通过静态 HTTP 服务打开，并明确标识为预览页；
- `docs/业务架构/总览.html` 能展示模块拓扑、黄金闭环、事实流、职责边界和一期/扩展五类视图；
- 预览页和总览页均能够进入七个模块页面；
- 销售页完整覆盖已确认的分批履约规则；
- 七个模块均标记为已确认，并覆盖各自最新状态、异常和边界；
- 任意业务架构页可跳到原型主入口；
- 任意现有原型页可跳到业务架构主入口；
- 空间切换链接不抢占主操作视觉；
- JavaScript 语法检查通过；
- 浏览器控制台无错误；
- 1440px 和 768px 宽度无横向页面溢出；
- 不出现仓库正式规格之外的已实现接口、状态或算法声明。

## 11. 非目标

- 不把业务架构和操作原型合并到同一 HTML；
- 不建设业务页与原型页的模块映射表；
- 不新增前端 Vue 路由；
- 不实现后端业务接口；
- 不引入第三方图形库或在线资源；
- 不实现财务、MRP、APS、退货、发货冲销等未进入一期范围的业务能力。

## 12. 2026-08-28 已批准补充：采购拒收与节点级角色

### 12.1 收货前拒收与收货后质量隔离

- `arrived_qty（到货数量） = rejected_qty（收货前拒收数量） + received_qty（实际接收数量）`。
- 仓库到货验收不填写质量数量，实际接收数量全部进入 `QualityHold（质量隔离位）`。
- 采购到货质检满足 `inspected_qty（检验数量） = qualified_qty（质检合格数量） + unqualified_qty（质检不合格数量）`。
- 收货前拒收数量不进入库存、不计入采购累计已收货并继续作为待收数量；拒收大于零必须填写原因并保留操作审计。
- 生产质检人员对质量隔离位中的全部实际接收货物进行检验；合格货物等待放行，不合格货物继续隔离。质量处置先形成业务决定，再由仓库人员确认实际移位、退回出库或报废扣减。

### 12.2 黄金闭环节点角色

总览页不再用“模块包含的全部角色”代替“当前节点实际角色”。黄金闭环的每个节点必须直接保存并展示自己的角色、输入、输出、状态、异常和事实来源；模块字段只作缺省回退。

| 节点 | 节点角色 |
| --- | --- |
| 关联采购来源 | 采购人员 |
| 到货验收、收货前拒收与实际接收 | 仓库人员 |
| 采购到货质量检验 | 生产质检人员 |
| 质量放行/报废决定 | 生产质检人员 |
| 退回供应方决定与协调 | 采购人员 |
| 质量处置实物执行与上架 | 仓库人员 |
| 生产领料 | 生产质检人员创建，仓库人员确认 |
| 工单审核、派工与工序执行 | 生产质检人员 |
| 成品入库 | 生产质检人员创建，仓库人员确认 |

为使角色与事实边界可读，原“收货质检上架”“审核派工执行”“成品分批入库”等复合节点必须拆分；本次只更新业务架构和正式规格，不提前改造高保真业务原型。
