# 2026-09-12—13 阶段 8 AI 与 Open WebUI 周末变更总结

> 整理日期：2026-09-14  
> 事实范围：2026-09-12—13 的阶段 8 实现，以及 2026-09-14 对这些改动进行的实机验证和交互补强  
> 事实依据：当前前后端代码、部署脚本、数据库迁移、正式规格和端到端验证结果

## 1. 总体变化

AI 助手从“WMS 直接请求模型生成文本”的初始纵向切片，演进为以下正式链路：

```text
WMS Vue AI 页面
  → Gateway / Core（WMS 用户、会话、租户和权限）
  → Windows 本地 Open WebUI（模型预设、Knowledge、Agent 工具编排）
  → 硅基流动 DeepSeek V4 Flash
  → WMS 专用只读 Tool Server
  → Core / IoT 授权业务事实
  → SSE 流式回答、来源摘要和审计
```

Open WebUI 只负责模型、知识检索和工具编排，不是 WMS 最终业务界面，也不保存或决定 WMS 权限和业务事实。

## 2. 已落地改动

### 2.1 Open WebUI 与模型接入

- Windows 本地固定安装 `open-webui==0.11.3`，默认只监听 `127.0.0.1:3000`；
- 通过硅基流动 OpenAI 兼容接口使用 `deepseek-ai/DeepSeek-V4-Flash`；
- 建立 `wms-assistant` 模型预设和 `wms` Tool Server；
- Core 默认使用 `open-webui` Provider，早期直连 DeepSeek Provider 只保留为诊断回退，同一次请求不会执行两套 Agent 循环；
- IDEA Core/IoT 运行配置可以加载被 Git 忽略的 `deploy/openwebui/windows.env`，密钥不写入 Run Configuration。

### 2.2 受控项目知识

- 新增 `docs/ai-knowledge/`，按 `knowledge-manifest.yaml` 只同步 7 份启用的 Markdown；
- 知识覆盖项目边界、术语、角色、黄金闭环、状态与阻塞规则、常见问题和工具目录；
- 知识文档只解释静态规则，订单、库存、任务、告警和操作历史仍必须查询 WMS 实时工具；
- Open WebUI 不直连 PostgreSQL，也不接收整个代码仓库、日志、密钥或历史计划。

### 2.3 十个只读工具

当前代码固定注册以下工具：

1. `queryTrace`
2. `queryOperationAudit`
3. `queryLowStock`
4. `queryInventoryByProductAndWarehouse`
5. `querySalesOrderStatus`
6. `queryPurchaseOrderStatus`
7. `queryWorkOrderProgress`
8. `queryQualityStatistics`
9. `queryDeviceAlarm`
10. `generateDailyOperationReport`

新增低库存专用读模型，按 `available_qty < safety_stock` 返回缺口，只提示、不自动补货。Tool Server 只读取 WMS AI 专用 OpenAPI `GET /v3/api-docs/ai-tools`，不导入整个业务 API。

### 2.4 权限、会话与安全边界

- AI 继承当前 WMS 登录用户的租户、有效 `jti` 和领域查看权限；
- 实际工具集合为“代码固定注册表 ∩ 部署启用名单 ∩ 当前用户权限 ∩ 本次请求限制”；
- Open WebUI 服务密钥只证明调用来自受控 Tool Server，不能替代 WMS 用户；
- chat/message 标识只用于 Redis 短期关联，工具回调时仍重新检查有效会话、实时权限、租户和调用次数；
- 当前没有向模型注册新增、修改、提交、审核、确认、完成、删除、SQL、Shell、文件系统、联网搜索或通用 HTTP 工具；
- 页面跳转动作已暂停，涉及多个角色时只返回主责、协同角色和建议顺序的文字说明。

### 2.5 会话、审计与业务操作历史

- Flyway V9 新增 AI 会话、消息和工具调用审计；成功、失败、超时和拒绝均有稳定状态；
- Flyway V10 新增 Core 服务结构化业务操作审计；业务事实仍以领域表和事实流水为准；
- 当前业务操作审计先落地销售订单创建、修改、提交、审核和人工完成五类成功动作；幂等成功重放不重复记录；
- `queryOperationAudit` 当前提供销售订单代表性切片，返回脱敏账号、动作、时间和状态变化，不返回原始凭据或幂等键；
- Auth、Core、IoT 后续仍需各自在服务边界补齐操作审计，不建设跨服务共同写入的万能审计表。

### 2.6 前端流式交互

- `/ai` 与 `/ai/chat` 使用真实 `fetch + ReadableStream` 解析命名 SSE；
- 支持 `meta`、`progress`、`tool_started`、`tool_finished`、`delta`、`done`、`error`；
- 页面展示回答增量、工具运行/完成状态、来源、数据时间、工具摘要、模型和 `request_id`；
- 支持停止生成；不展示模型思维链，不展示页面跳转按钮；
- 2026-09-14 补齐 Open WebUI 后台工具回调到浏览器的工具生命周期事件，同一调用的开始和完成使用同一个 `call_id`；工具超时错误码统一为 `AI_TOOL_003`。

## 3. 实机验证结论

以下均通过 WMS 登录、Gateway、Core、Open WebUI、硅基流动模型和 WMS Tool 的完整链路验证，不是直接调用 Java 方法：

| 模块 | 角色 | 验证结果 |
| --- | --- | --- |
| 销售 | 销售人员 | 销售订单状态与履约数量查询成功 |
| 采购 | 采购人员 | 采购订单状态、订购/已收/待收数量查询成功 |
| 库存 | 仓库人员 | 指定产品仓库库存与低库存缺口查询成功 |
| 制造 | 生产质检人员 | 工单计划、报工、合格、不良、入库和阻塞查询成功 |
| 质量 | 生产质检人员 | 近 7 日质量统计查询成功 |
| IoT | IoT 人员 | 无告警时返回真实零值，没有凭行业常识编造告警 |
| 跨域 | 销售等授权角色 | 追溯按关联对象权限裁剪，只报告隐藏节点数量 |
| 综合 | 租户管理员 | 日报组合六类授权事实，缺失或陈旧数据明确标识 |
| 权限负向 | 销售人员 | 请求采购工具被拒绝并写入 `Denied / AI_TOOL_002` 审计 |

六个演示账号的能力目录分别返回 10、8、8、10、10、4 个权限交集工具。浏览器实测已显示“查询低库存 / 已完成”工具卡、来源、数据时间、工具名和请求编号。

自动化与构建证据：

- Open WebUI 工具生命周期、上下文和超时错误码聚焦测试 16 项通过；
- `platform-shared` 18 项、`platform-core` 215 项测试通过；
- 前端 15 项单元测试通过，生产构建成功；
- 当前 Core 错误日志为空，仓库文件未发现硅基流动或 Open WebUI API Key。

## 4. 尚未完成

- 十个工具尚未完成每项“成功、空数据、非法参数、无权限、跨租户、超时、审计”的全组合实机矩阵；
- 仍需真实注入硅基流动 429/5xx、Open WebUI 中断、工具执行中 `jti` 失效和临时聊天清理失败；
- 前端会话历史页和 AI 工具审计查询页尚未完成；
- 业务操作审计尚未覆盖 Core 其他领域、Auth 和 IoT 的成功/失败/拒绝动作；
- AI 继续保持只读，写操作、自动执行、页面跳转、自动定时报表和外部联网搜索不在一期范围。
