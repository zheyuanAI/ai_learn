# 阶段 8 AI 现有业务接口与统一白名单改造记录

> 日期：2026-09-14  
> 结论：代码改造、配置脚本、文档同步和自动化回归已完成；真实 Open WebUI 多角色端到端验证及旧十工具删除尚未执行。

## 一、本轮目标

将 AI 查询从“每项业务能力再写一套 AI 专用 Controller、DTO 和 Tool”调整为：

1. 页面和 AI 复用现有业务查询接口；
2. `deploy/openwebui/wms-ai-api-whitelist.yml` 作为唯一人工维护的 AI 业务 API 白名单；
3. Open WebUI 读取 Gateway 根据该白名单裁剪生成的 OpenAPI；
4. Gateway 把工具调用恢复为当前 WMS 对话用户和租户；
5. 下游现有 Spring Security、`@PreAuthorize`、租户隔离和领域规则继续做最终授权；
6. 当前白名单只开放查询操作，暂不开放增删改、审核、确认和执行类操作。

核心边界：白名单决定 AI 可以尝试调用什么，Spring Security 决定当前用户实际可以调用什么，大模型负责选择接口、多步联查和解释结果。

## 二、首批白名单

首批共登记 36 个精确的 `GET + path` 操作，其中 Core 30 个、IoT 6 个。分组只服务于清单可读性和模型工具说明，不复制角色权限。

| 分组 | 数量 | 主要能力 |
| --- | ---: | --- |
| 主数据 | 6 | 商品、仓库、库位搜索与详情 |
| 销售 | 3 | 销售订单搜索、详情和直接拣货履约查询 |
| 采购 | 3 | 采购订单搜索、详情和上架任务查询 |
| 库存 | 4 | 余额、预留、流水和低库存查询 |
| 制造 | 4 | 工单搜索、详情和工序执行查询 |
| 看板 | 8 | 库存、履约、制造、质量、设备、告警、追溯摘要及异常中心 |
| 追溯与审计 | 2 | 黄金闭环追溯和账号操作时间线 |
| IoT | 6 | 设备、状态、遥测和设备告警查询 |

首批未开放设备凭证、用户权限管理、库存调整、订单审核、任务完成、发货确认、告警确认等敏感或写操作。以后扩展普通业务查询时，只需实现或复用业务接口，并在这一份 YAML 中增加精确 operation；无需再增加 AI 专用接口层。

## 三、已完成改造

### 3.1 单一白名单和工具目录

- 新增唯一清单 `deploy/openwebui/wms-ai-api-whitelist.yml`；
- Gateway 启动时校验清单版本、服务、operation ID、HTTP Method 和路径；
- Gateway 从 Core/IoT 原始 OpenAPI 中只保留清单操作，生成：
  - `GET /v3/api-docs/ai-tools`
  - `GET /v3/api-docs/ai-tools/core`
  - `GET /v3/api-docs/ai-tools/iot`
- 过滤文档使用 YAML 中稳定的 operation ID 和中文摘要，并把工具请求统一指向 Gateway；
- `configure-windows.ps1` 根据 Gateway 目录自动配置 `server:wms_core` 和 `server:wms_iot`，不再硬编码完整工具列表。

### 3.2 委托当前登录用户

- Core 发起 Open WebUI 请求前，在 Redis 保存短时、限次的用户委托上下文；
- Open WebUI 工具请求只携带服务密钥、ChatId 和 MessageId，不直接携带可伪造的用户权限；
- Gateway 校验服务密钥、精确白名单、委托上下文、调用次数和当前有效 JTI；
- Gateway 清理调用方可能伪造的身份 Header，再注入受信任的用户、租户、会话和请求上下文；
- Core/IoT 继续通过原有下游安全过滤器读取最新权限，并由现有 `@PreAuthorize` 作最终决定；
- Gateway 不维护角色与权限映射，YAML 也不保存角色或权限编码。

### 3.3 复用普通业务接口

- 销售、采购、工单、库存、主数据、看板、追溯、设备和告警直接复用现有查询 API；
- 补充普通业务接口 `GET /api/inventory/low-stock`，复用现有低库存查询服务；
- 补充普通业务接口 `GET /api/operation-audits`，复用现有业务操作审计服务；
- 这两个接口是页面和 AI 均可使用的普通业务能力，不属于 AI 私有接口。

### 3.4 交互与审计

- Open WebUI 模式不再通过旧 Java 工具注册表确定业务能力；
- `/api/ai/capabilities` 在 Open WebUI 模式下返回 YAML 派生的 operation；
- 保留 SSE 工具开始、完成、失败等进度事件；
- Gateway 记录 operation、输入摘要、输出摘要、HTTP 状态和耗时，Core 写入既有 AI 工具审计；
- 前端补充 36 个 operation 的中文展示名称，并兼容历史会话中的旧工具名称。
