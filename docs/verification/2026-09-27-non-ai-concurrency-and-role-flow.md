# 非 AI 并发修复与六岗位真实链路验收

日期：2026-09-27。范围：库存、采购、销售、制造、IoT、前端重试及工程验证。AI 功能没有改动；沿用必要的租户、权限、幂等和事务一致性检查。

> 历史记录说明：本文保留 2026-09-27 的首轮结果。采购订单行累计事实、MQTT 提交后确认和后续隔离并发写入/持续读取已在 [2026-09-28 后续验收记录](2026-09-28-non-ai-followup.md) 完成，以后者为当前状态。

## 已落地的改动

- 库存应用端口提供整笔业务维度预锁，生产环境要求已有事务。采购收货、销售拣货/退拣/释放/发货/终止、调拨、盘点和多行领退料，在首次库存写入前取得全部维度的固定顺序锁。销售与领料的预先选批同时累计本次已计划数量，避免下一行重复消耗同一余额。
- IoT 摄取由实例级串行改为租户与设备级串行，同一设备持有锁至事务提交或回滚，不同设备允许并行；持有者和等待者归零后移除锁。数据库唯一去重和时间戳保护继续保留。
- 非 AI `useCommand` 调用冻结首次对象 ID、载荷和事件时间。重试成功执行原命令的刷新与关窗；切换对象或编辑新草稿后保留当前编辑。收货、发货和预留子弹窗暴露实际草稿快照，同单刷新不覆盖在编表单。
- 采购订单创建、修改、提交、审批、人工终止及收货的首次成功操作，写入已有 Core 操作记录表，与业务同事务；同键重放不重复记录。查询按采购或销售对应的查看权限校验。其他领域的操作记录及失败操作记录未在本次扩展。
- 修正 Auth 迁移测试的旧版本数量断言与文本 `MAX(version)` 排序问题，改为读取最后安装的版本；静态引用检查在遍历入口跳过依赖、运行时和生成目录，避免读取数据库文件。未修改认证生产逻辑。
- 追溯合并保留权限和租户过滤；取得实体自身的真实事实后，替换此前的上下文引用或通用占位状态，优先保留实际更新时间。补充三来源不同返回顺序以及越权/跨租户不能升级节点的回归。
- 新增 GitHub Actions 构建回归、真实隔离 PostgreSQL 测试参数和只执行 GET 的逐级负载脚本。CI 配置已在本地核验，尚未推送或运行远端工作流。
- 浏览器复现正常退出返回 HTTP 200，却被登录页误报为会话过期。登录页改为只对明确的 `reason=401` 显示失效提示，正常退出不再误报。
- 浏览器发现采购详情缺失名称、把未返回的累计数量展示为 0；现通过主数据明细补名称，缺失事实明确标注“未提供”。MES 详情接回已实现的领退料查询，通过工序 ID 对应路线明细，缺少设备名称时保留实际设备 ID；整组详情查询只允许当前工单/请求世代回写。
